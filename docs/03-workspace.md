# 03. 工作区与提交

工作区模块负责管理未提交的改动、暂存操作以及最终的提交执行。为了保持操作连贯性，该模块与历史视图深度整合。

## 核心职责

- **状态感知**：实时感知工作区（Working Directory）与暂存区（Index）的变动。
- **改动管理**：提供灵活的暂存（Stage）、取消暂存（Unstage）以及文件级 / 区块级丢弃改动（Discard）操作。
- **提交执行**：支持创建新提交、修补 HEAD 提交（Amend）以及提交信息的草稿管理。

## 视图整合策略

工作区视图不占用独立路由，而是作为历史列表顶部的**虚拟项 (WIP 行)** 存在。
- **入口**：点击 WIP 行会激活详情面板的工作区模式。
- **联动**：在工作区模式下选中文件，会触发右侧 Diff 查看器的实时加载。
- **自动显隐**：当工作区完全干净（无任何未暂存或暂存变动）时，WIP 入口自动隐藏。

## 数据模型

后端提供的状态数据包括以下核心维度（详情见 `src/types/git.ts::WorkspaceStatus`）：
- **分类清单**：区分已暂存（Staged）、未暂存（Unstaged）及未追踪（Untracked）文件。
- **文件元数据**：包含路径、状态标识（新增/修改/删除/重命名/类型变更/冲突）以及基础的行列差异统计，未跟踪文件也会在状态列表中展示新增行数。类型变更用于普通文件、符号链接、gitlink 等文件类型变化，即使没有文本增删也必须展示。
- **上下文信息**：当前分支名、是否处于游离（Detached）状态、HEAD 提交信息（用于 Amend 回填）。

## 交互设计要点

### 文件操作
- **选择与多选**：支持单选查看 Diff，以及通过组合键或拖拽范围进行多选批量操作。
- **快捷动作**：行内提供快速暂存/撤销按钮；普通文件可双击复用现有系统编辑器打开动作，删除项、目录和 Submodule 不触发；右键菜单提供路径复制、文件系统跳转、编辑器关联及忽略（`.gitignore`）管理。复制文件名、相对路径或绝对路径后显示统一成功反馈，剪贴板失败使用非阻塞错误提示。
- **键盘审阅**：WIP 视图支持用方向键连续浏览文件，并用可配置快捷键暂存 / 取消暂存当前文件或全部文件。文件跨分区后保持同一路径选择和列表焦点，Diff 自动切换到对应 staged / unstaged 侧；异步操作期间若用户已经改选其他文件，则不覆盖新选择。
- **排序偏好**：列表视图下，文件右键菜单可将单个或多选文件移到最前 / 最后，或恢复默认位置；该偏好按仓库路径独立保存，并复用到提交详情变更文件列表。树形视图保持目录结构与字母序，不提供排序动作。
- **Submodule 项**：当工作区条目路径对应当前仓库的 direct submodule 时，列表以专用图标标记，并在右键菜单提供打开该 submodule 仓库的动作；未初始化或工作区缺失时可直接 init / update。暂存 / 取消暂存仍按父仓库 gitlink 变更处理。
- **批量管理**：支持一键暂存所有、取消所有以及丢弃所有改动的全局操作。多选和目录级暂存 / 取消暂存、批量丢弃都通过一次 IPC 完成，并且只触发一次状态刷新，避免按文件重复打开仓库和刷新列表。
- **丢弃恢复**：文件级、批量和全部丢弃会先把当前工作区原件移入系统废纸篓，再恢复 Git 基线；系统废纸篓不可用时操作失败，不降级为永久删除。文件级恢复到 Index，全部丢弃恢复到 HEAD；ignored 文件和 Submodule 工作目录不被移走。Hunk 级丢弃仍是局部反向 patch，不承诺废纸篓恢复。
- **丢弃确认**：单文件和多选丢弃使用应用内确认框，多选会预览最多五个具体路径和剩余数量；全部丢弃窗口展示 staged / unstaged / untracked 分类统计。请求绑定打开确认框时的仓库、HEAD 与去重路径快照，后端在任何文件移入废纸篓前再次复核；确认后新增或移除路径会拒绝旧请求。执行中保持窗口可见并禁用重复提交，失败进入统一 Toast。
- **区块级操作**：WIP Diff 开启按 Hunk 分组时，未暂存侧可暂存或放弃单个 Hunk，已暂存侧可取消暂存或放弃单个 Hunk。暂存 / 取消暂存只修改 Index；放弃未暂存 Hunk 只改工作区，放弃已暂存 Hunk 同时改 Index 和工作区。

### 提交表单
- **弹性输入**：支持自动增长的提交信息输入框。草稿按仓库规范路径自动保存在本地，切换仓库和重启应用后恢复各自内容；后端临时仓库 ID 不参与持久化键，避免重启后失配。
- **摘要引导**：操作栏实时显示提交消息首行的 Unicode 字符数；50 字符内保持中性，51–72 使用提醒色，超过 72 使用警示色。它只提供可读性建议，不阻止提交，也不受正文长度影响。
- **快速聚焦**：可配置快捷键会直接聚焦提交信息输入框并把光标放到草稿末尾，与暂存快捷键组成全键盘提交路径。
- **Amend 机制**：勾选 Amend 时，表单会自动回填上一条提交的信息，并允许在不产生新暂存变动的情况下仅修改提交信息。普通 Commit 与 Amend 都绑定提交时的 repoId、HEAD OID 和完整 ref；引用变化时后端拒绝旧请求。
- **提交准则**：根据暂存区是否为空、HEAD 是否存在等状态，动态控制提交按钮的可用性。
- **中间态边界**：Merge / Rebase / Cherry-pick / Revert 等 Git 操作进行中时，普通提交与 Amend 控件禁用；用户必须使用操作横幅的 Continue / Abort，避免绕过专用父链与状态清理逻辑。
- **草稿消费安全**：普通提交、Amend 或使用草稿作为 Stash 消息成功后，仅当对应仓库草稿仍与操作发起时原文一致才清除。等待期间的新输入和其他仓库草稿不会被完成回调覆盖；操作失败则保留原文。
- **最近提交撤销**：普通提交成功后，顶部工具栏临时提供 Undo。候选仅属于当前窗口和仓库；切换仓库、HEAD 变化、再次提交或 Push 后失效。撤销使用 mixed reset 把提交改动恢复到未暂存工作区，空草稿会恢复原提交信息；已有新草稿不会被覆盖。

## 后端集成

- **状态获取**：调用 Git 引擎，结合文件监听系统实现状态的按需刷新。
- **暂存逻辑**：通过索引操作实现文件级和 Hunk 级的精细化管理。`stage_files` / `unstage_files` 在同一仓库与 Index 实例中处理全部路径并统一写盘；暂存已删除文件时从 Index 移除对应路径。
- **提交构建**：负责生成包含作者/提交者签名、Tree 对象及 Parent 链接的提交实体。`WorkspaceStatus` 提供后端解析的完整 HEAD ref（含 unborn 与 detached 边界），提交写入前要求仓库 clean 并复核该 ref 与 OID。
- **撤销安全**：最近提交撤销在后端原子校验预期 HEAD、本地分支、单父提交和已知 upstream 发布状态；不满足边界时拒绝改写历史并提示使用 Revert。
- **丢弃操作**：`discard_file` / `discard_files` 将目标原件送入系统废纸篓后从 Index 恢复已跟踪文件；`discard_all_changes` 在移动原件前先解析 Git 基线，有 HEAD 时 hard reset 并同时恢复 Index 与工作区，无首个提交时清空 Index。gitlink 只恢复父仓库记录，不移动 Submodule 工作目录。

## 性能与刷新机制

- **自动刷新**：通过订阅后端的文件变动事件，工作区状态与当前 Diff 视图通常会自动保持最新。
- **手动刷新**：顶部工具栏和全局快捷键提供当前仓库重载入口，会重新读取工作区、历史、分支、标签、stash、submodule 和当前 WIP Diff，用于文件监听或外部同步未及时反映的场景。
- **缓存快照**：在多仓库切换过程中，各仓库的工作区状态会被临时快照，以实现秒级的切换回访。
- **草稿存储**：每个仓库只读写自己路径对应的一条短文本记录，不在每次输入时序列化全部仓库草稿，也不触发 Git 状态刷新或 IPC。
- **状态统计**：状态列表只计算文件级增删行统计；完整 Diff 内容由 Diff 查看器按需加载。
- **批量索引操作**：多选和目录级暂存 / 取消暂存复用一个仓库与 Index，统一写盘后前端只刷新一次；相较逐文件调用，IPC 和状态扫描次数从文件数 N 降为固定各一次。
- **批量丢弃**：多选文件由单个命令复用同一仓库句柄和 Checkout，完成后前端统一刷新一次；操作量仍与选中文件数线性相关，不引入额外状态扫描。
