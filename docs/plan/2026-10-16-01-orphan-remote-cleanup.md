# 清理无配置的远程跟踪引用

## Context

远程树由配置和跟踪分支共同生成。删除配置后残留的 `origin_p/main` 仍会形成节点，但原删除流程找不到配置时直接报上下文变化，无法清理。

预期结果：无配置节点可确认清理本地跟踪引用，配置存在的节点保持原删除保护。

## 关键决策

- 原 `remove_remote` 仍要求配置存在，不复用空 URL 表达配置缺失。
- 独立清理命令只接受无对应配置的节点，确认展示完整引用数量；后端校验完整名称及直接 / 符号目标快照，并锁定引用后再复核、删除。
- 清理严格限定 `refs/remotes/<name>/`，不操作服务器、工作区、本地分支或其他远程配置。
- 仅在用户打开删除确认时扫描该节点引用，不增加状态刷新热路径开销。
- 实际问题仓库只读核对，回归删除在临时仓库进行。

## 验证方式

1. 临时仓库创建没有配置的跟踪引用与符号 HEAD，确认后均被清理；其他远程与本地分支保留。
2. 确认期间引用增删 / 目标变化或出现同名配置，后端拒绝旧快照。
3. 前端确认期间切仓或同名配置出现时拒绝操作，正常配置删除回归通过。
4. 执行项目要求的四项类型、编译与测试检查。
