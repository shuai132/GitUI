# 原子覆盖安装插件

## Context

`install_plugin_from_path` 安装同 ID 插件时先递归删除现有目录，再把源目录复制到目标。复制失败、磁盘空间不足或 manifest 在复制期间变化时，会留下缺失 / 不完整插件；旧版本没有回滚点。插件设置页把这条路径同时用于首次安装与更新本地插件，因此失败不应破坏当前可用版本。

预期结果：先把源插件完整复制到扫描目录之外的暂存区并重新验证 manifest；覆盖时先把旧版本移到备份区，切换成功后才把备份移入系统废纸篓。复制、切换或废纸篓步骤失败时回滚旧目录，保持列表中的可用插件不变。

## 关键决策

- 暂存与备份目录放在应用数据目录的独立安装事务根目录，不位于 `plugins/` 扫描根目录，避免并发刷新显示临时副本。
- 使用同一应用数据卷上的 rename 完成目录切换；不把递归 copy 直接写入正式目标。
- 旧版本只有在新版本已位于正式目标后才移入废纸篓；若该步骤失败，则移除新副本并把旧目录 rename 回目标。
- 用户选择的源目录始终只读；回滚时删除的是刚复制的暂存 / 新副本。
- source 已经等于正式 target 时沿用现有“只启用”语义，不对自身做覆盖事务。

## 验证方式

1. 首次安装成功后正式目录完整，暂存目录无遗留。
2. 覆盖成功后新版本生效，旧版本进入系统废纸篓。
3. 模拟复制失败，旧版本仍在正式目录，新版本不出现。
4. 模拟正式目录切换失败或废纸篓失败，旧版本恢复，新副本被清理。
5. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
