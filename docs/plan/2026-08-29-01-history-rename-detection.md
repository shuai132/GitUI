# 历史提交重命名识别

## Context

Git 的提交对象只保存树快照，文件重命名需要在父提交与当前提交的 diff 上按内容相似度推断。当前历史详情直接解析 libgit2 的原始 tree diff，未执行相似度检测，因此高相似度的路径移动会显示为一条删除和一条新增；单文件 diff 也只按新路径查询，无法还原重命名前后的内容变化。

预期结果是历史提交详情把达到默认相似度阈值的删除 / 新增配对为一个重命名项，在文件列表和 Diff 标题中展示“旧路径 → 新路径”，并继续按真实内容变化展示增删统计与 hunk。

## 关键决策

- 使用 libgit2 的 rename similarity 检测和默认 50% 阈值，不自行实现内容匹配算法，以保持与常见 Git 展示语义一致。
- 只识别 rename，不启用 copy detection 或 rewrite 拆分；保留 libgit2 默认候选上限，避免极端提交中的无界相似度比较。
- 提交概览在完整 tree diff 上识别后再解析；单文件正文只把已知的旧 / 新两个路径作为候选，避免点击文件时重新扫描整次提交。
- 列表排序、树结构、右键操作和文件打开仍以新路径为主；“旧路径 → 新路径”只承担用户可见的重命名表达。

## 验证方式

1. 构造一个提交：移动文本文件并修改少量内容，确认概览只返回一个 `FileDiff`，旧 / 新路径正确且状态为 renamed。
2. 按旧 / 新路径加载该文件，确认正文只包含真实修改行，不把整个文件显示为删除和新增。
3. 验证列表和 Diff 标题均显示“旧路径 → 新路径”，普通新增、删除、修改文件展示不变。
4. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
