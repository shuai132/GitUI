# Markdown 文件预览增强

## Context

当前文件 Diff 只显示 Markdown 源码，长段落需要横向滚动，无法阅读修改后的完整文档或 Mermaid 图表。增加源码差异、修改后预览、渲染对照三种显示方式，保留原有 Git 区块操作，并让显示偏好跨会话生效。

## 关键决策

- 默认保持源码差异，Markdown 源码默认换行；用户显式切换预览后记住选择，其他文件不受影响。
- 预览完整文档，绝不把 hunk 拼接成所谓的完整修改后内容。复用已有字节读取 IPC，暂存预览不混入工作区后续修改。刷新绑定当前 Diff 对象，过期请求不能覆盖新文件。
- 修改后预览只读取新侧，对照才读取旧侧；源码按 hunk 查看时不加载预览依赖。文档大小与图表复杂度设限，超限提供源码入口，Mermaid 按可见范围排队渲染，避免启动和状态刷新热路径增加全量解析。
- Markdown 使用独立 Marked 实例，避免影响更新日志。HTML 经 DOMPurify 消毒；Mermaid 使用 strict 安全配置，图表输出隔离在图片中，禁止文件内容改变应用配置或执行脚本。
- 本轮不增加仓库树资源 IPC；相对图片 / 文件链接明确提示无法在预览中解析，不错误地从应用 URL 或另一版本工作区读取。网络图片由用户主动开启。
- 渲染对照是完整两侧的阅读视图，精确增删与暂存 / 放弃仍由源码差异承担。

## 验证方式

- 单元测试覆盖完整内容来源选择、编码、刷新竞态、删除 / 空文件、Markdown 消毒、GFM、Mermaid 错误与过期渲染、偏好持久化及模式切换。
- 浏览器使用工作区、暂存和历史场景测试：外部保存后刷新、三种模式切换、长行左右对齐、目录 / 锚点、代码复制、有效与无效 Mermaid、浅深主题、窄面板及大文档降级。
- 检查按需构建分包，并在含上万提交的测试仓库场景验证新增路径不加载历史全量内容。
- 执行 `npx vue-tsc --noEmit`、`npm run test`、`cargo check`、`cargo test` 与前端生产构建。前端无格式化器配置，不引入临时工具。
