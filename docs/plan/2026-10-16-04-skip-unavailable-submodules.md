# 启动时不保留打开失败的子模块仓库

## Context

启动恢复把所有打开失败的持久化路径保留为不可用仓库。子模块目录可能随父仓库切换分支消失，此时不应在「所有仓库」末尾持续留下重试项。需要能够识别当前分支已移除的子模块，同时继续保留普通仓库的恢复能力。

## 关键决策

- 只处理启动时 `open_repo` 失败的记录；成功打开的子模块仍照常显示。
- 通过祖先 Git 仓库的当前子模块声明和保留的 modules 元数据确认子模块路径，不按路径包含关系猜测，以免清除普通嵌套仓库。
- 批量识别只遍历 Git 子模块元数据，不遍历工作区或对象库；同一个祖先仓库只处理一次，不依赖持久化列表中的父子顺序，也兼容父仓库未加入名册。
- 被确认的失败子模块不加入不可用列表，并从持久化路径移除；重启后不会反复出现。识别无法确认或命令异常时保留原恢复行为。
- 不改变普通仓库的重试、重新定位与移除操作，不改变用户主动打开仓库的错误提示。

## 验证方式

- 临时真实仓库验证当前声明的未初始化子模块、切分支后声明和目录均消失的子模块、自定义名称与多层路径、普通嵌套仓库和无 Git 祖先的路径。
- 前端验证失败子模块被清理、正常子模块与普通失败仓库保留、被移除项原为活跃路径时的回退、识别命令失败时的保守行为。
- 执行 `cargo fmt`、`npx vue-tsc --noEmit`、`npm run test`、`cargo check`、`cargo test`。
