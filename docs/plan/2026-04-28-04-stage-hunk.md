# 暂存区块

## Context

当前 Diff 查看器已经支持提交 diff 的“回滚区块”，但工作区 diff 只能按文件粒度暂存或取消暂存。用户在一个文件里只想提交部分变更时，需要离开 GitUI 使用命令行或其他工具。

目标是在 WIP diff 的按 Hunk 分组视图中提供区块级索引操作：未暂存侧可以“暂存区块”，已暂存侧可以“取消暂存区块”。操作只修改 index，不直接改工作区内容；完成后刷新工作区状态和当前 diff。

## 关键决策

- **只在按 Hunk 分组时显示按钮**：与现有“回滚区块”的可见条件一致，完整文件视图保持阅读优先，不在行间插入操作入口。
- **后端暴露通用 index patch IPC**：前端负责根据当前 diff 构造正向或反向 patch，后端只负责把 patch 应用到 index，避免为每种 hunk 操作定制命令。
- **未暂存侧正向应用、已暂存侧反向应用**：未暂存 diff 表示 index → worktree，正向应用到 index 即暂存；已暂存 diff 表示 HEAD → index，反向应用到 index 即取消暂存。
- **新增 / 删除文件走文件级兜底**：libgit2 不接受把新增文件的 `/dev/null` patch 直接应用到 index；这类 WIP diff 实际只有整文件 Hunk，因此通过已有文件级 stage / unstage 完成。
- **不处理二进制 diff 的区块操作**：二进制文件没有文本 hunk，继续只能文件级暂存/取消暂存。

## 验证方式

- 前端：运行 `npm run test` 覆盖 hunk patch 构造和按钮展示逻辑。
- 后端：运行 `cd src-tauri && cargo test` 覆盖单个 hunk 暂存与取消暂存。
- 类型与编译：运行 `npx vue-tsc --noEmit`、`cd src-tauri && cargo check`。
- 手动验证：在同一文件制造两个相隔较远的修改，确认只暂存其中一个 hunk 后，未暂存和已暂存区域分别显示剩余/已暂存的区块；再从已暂存侧取消暂存一个 hunk。
