# 支持启动时自动检查开发版更新

## Context

开发版更新通道已经支持在设置页手动检查，但希望尝鲜的用户仍需每次主动操作。需要增加一个独立、默认关闭的设置，让用户可选择在启动时检查 `main` 分支最新成功构建，同时不改变正式版更新策略，也不静默安装更新。

预期结果是：用户开启开发版自动检查后，应用启动时优先检查开发版通道；发现新构建时展示带开发版警告的更新对话框。若开发版没有可用更新或检查失败，再按原有设置决定是否检查正式版，避免一次启动弹出两个更新提示。

## 关键决策

- 开发版自动检查使用独立布尔设置，默认关闭；升级后的既有用户也保持关闭，只有主动开启才进入开发版通道。
- “自动更新”沿用现有正式版语义：启动时自动检查并提示，由用户确认后下载和安装，不静默安装。
- 开发版自动检查开启时优先查询开发版；若发现更新，本次启动不再检查正式版，避免两个对话框竞争。开发版无更新或失败时，正式版仍按原有自动检查策略执行。
- 开发版检查仍不读取或写入正式版的跳过版本与上次检查时间，保持两个通道的状态隔离。
- 继续复用现有 `check_development_update` IPC 和 Tauri updater 资源，不新增 IPC 契约。

## 验证方式

1. 单元测试确认新设置默认关闭、可持久化，并能从更新设置页切换。
2. 单元测试确认开发版关闭时不检查、开启时优先检查、找到开发版后不再检查正式版，以及开发版无更新或失败时正式版兜底。
3. 运行前端类型检查与全部单元测试。
4. 运行 Rust 格式化、编译检查与全部单元测试。
5. 推送后等待 GitHub Actions 构建与测试成功，并确认开发版更新清单完成部署。
