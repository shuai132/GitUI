# 工作区丢弃应用内确认

## Context

工作区的单文件与多选丢弃仍依赖 WebView 原生 `confirm()`；仓库既有记录表明该对话框在 macOS Tauri 环境中可能被吞，用户点击后会看到静默无反应。多选确认只显示数量，不展示具体路径；“丢弃全部”虽已有应用内窗口，但提交后立即关闭、没有 loading，失败又使用原生 `alert()`。

GitHub Desktop 的丢弃流程使用应用内确认窗口，让用户在最终执行前复核受影响文件。GitUI 已经把文件原件移入系统废纸篓，因此本次只补齐前端确认与执行反馈：单文件 / 多选使用统一确认框，多选预览具体路径，全部丢弃保留现有分类统计并显示执行态。

## 关键决策

- 不改丢弃 IPC 和废纸篓策略；本次优化现有入口的可达性、目标可见性与执行反馈。
- 多选请求在打开确认框时复制路径数组，不在确认时重新读取当前选择，避免 UI 状态变化后确认另一组文件。
- 路径预览最多展示五项，超过部分显示剩余数量；大批量选择不会撑高对话框或降低确认速度。
- 单文件 / 多选复用 `ConfirmDialog`；全部丢弃保留现有分类统计 Modal，因为 staged / unstaged / untracked 的影响说明比单段文本更清楚。
- IPC 错误继续由 errors store 映射到 `ToolbarToast`，确认逻辑只处理本地上下文失效提示，避免同一失败弹两次。

## 验证方式

1. 从文件右键菜单触发丢弃，确认对话框展示完整相对路径；取消后文件不变。
2. 选择 2 个和超过 5 个未暂存文件，确认路径预览与剩余数量准确，确认后只丢弃打开窗口时捕获的路径。
3. 打开单文件 / 多选确认后让 active repo 变化，确认旧请求取消且没有 IPC 写操作。
4. 执行单文件、多选和全部丢弃，确认 loading 期间不能关闭 / 重复提交，成功后清理对应选择。
5. 模拟 IPC 失败，确认窗口关闭且统一 Toast 可见，没有原生浏览器弹窗。
6. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
