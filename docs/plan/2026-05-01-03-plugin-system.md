# 插件系统

## Context

GitUI 需要一个本地可信的插件系统，让高级用户和团队把常用 Git 工作流、外部服务和本地脚本接入应用，而不必把所有垂直能力都内置进核心。第一版目标是可安装、可启用、可执行、可管理，并把插件命令注入现有 Actions 菜单。

## 关键决策

- 做本地可信插件，不做第一版市场和签名。这样能先服务本机自动化和团队内部插件。
- 插件不能直接访问主应用 Vue/Pinia/Rust 内部状态，只能通过 Host API/IPC 进入 GitUI 能力边界。
- 第一版优先命令和菜单贡献点；面板和设置贡献点先在 manifest 中建模，渲染能力后续接入。
- 后端插件以本地进程 JSON-RPC 执行。GitUI 负责传入上下文、收集输出和把刷新需求交还给前端。
- 插件引发仓库变化时由返回值声明刷新域，避免每次都全量刷新历史和工作区。

## 验证方式

- 放置或安装一个带 `plugin.json` 的本地插件目录。
- 在设置页确认插件能列出、启用、禁用和卸载。
- 在 Actions 菜单确认 `toolbar.actions` 命令出现，执行后能显示返回消息。
- 后端命令执行能处理正常 JSON-RPC 响应、纯文本输出和异常退出。
- 提交前运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
