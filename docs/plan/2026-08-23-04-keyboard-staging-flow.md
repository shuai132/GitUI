# 工作区全键盘暂存流程

## Context

GitUI 工作区已经支持上下方向键浏览文件，也具备文件级与全部暂存 / 取消暂存命令，但执行动作仍依赖行内按钮或鼠标菜单，提交信息框也没有直接聚焦入口。高频审阅流程会在“选文件、暂存、继续选、填写信息”之间反复切换输入设备。

同类产品已经形成稳定键盘模型：

- [GitKraken 官方快捷键](https://help.gitkraken.com/gitkraken-desktop/keyboard-shortcuts/)提供 `S/U` 暂存 / 取消暂存当前文件、`Cmd/Ctrl + Shift + S/U` 处理全部文件，以及 `Cmd/Ctrl + Shift + M` 聚焦提交信息。
- [VS Code 用户反馈](https://github.com/microsoft/vscode/issues/207066)描述了用上下键与 Space / Enter 逐个审阅暂存的实际流程，并指出暂存后丢失文件列表焦点会直接打断该流程。

本阶段复用 GitUI 现有可配置快捷键与 Git 命令，补齐工作区键盘动作，并在文件跨未暂存 / 已暂存分区后保持路径选择、焦点与 Diff 连贯。

## 关键决策

- 默认键位沿用 GitKraken，降低熟悉桌面 Git 客户端用户的学习成本；所有动作继续允许在 GitUI 设置中改绑或清除。
- 单文件动作只在 WIP 视图且存在当前文件时生效；`S` 不会错误取消暂存，`U` 也不会错误暂存。
- 全部动作只在对应分区非空时执行；长按产生的 repeat 事件会被消费但不重复发起 Git 操作。
- Git 操作完成后，仅当仓库、选中路径和 Diff 侧都未被用户改变时，才把 Diff 切到目标侧，避免异步完成覆盖用户的新选择。
- 不新增 IPC；复用 `workspace` store 的现有命令和刷新路径。

## 验证方式

1. 在 WIP 文件列表用上下键选择未暂存文件，按 `S`，确认文件进入已暂存区、仍被选中且 Diff 切到 staged 侧。
2. 选中已暂存文件按 `U`，确认反向迁移；在错误分区按键不执行 Git 命令。
3. 使用 `Cmd/Ctrl + Shift + S/U` 暂存 / 取消全部，确认当前路径存在时保持选择和正确 Diff。
4. 使用 `Cmd/Ctrl + Shift + M` 聚焦提交信息，输入后原有提交快捷键仍生效。
5. 在提交输入、搜索输入、终端与非 WIP 视图确认单键动作不会误触发；设置中改绑 / 清除后立即生效。
6. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
