# 批量暂存与取消暂存

## Context

WIP 多选和目录行目前通过循环调用单文件 store 方法来暂存 / 取消暂存。每个文件都会重新打开仓库、写一次 Index，并在前端重新调用 `get_status`；选择 100 个文件时就是 100 次变更 IPC 加 100 次全量状态刷新，延迟随文件数线性放大，列表还会反复重绘。

预期结果：新增批量暂存与取消暂存命令，一次复用仓库和 Index，所有路径处理完成后只写一次 Index、只刷新一次状态。单文件入口继续保留并复用同一批量实现，用户可见语义不变。

## 关键决策

- 批量方法复用一个 Repository 和 Index，并在全部路径成功处理后统一 `index.write()`；不为每个文件单独落盘。
- 有 HEAD 时，批量取消暂存复用一次 pathspec reset；无 HEAD 时从 Index 逐项移除后统一写盘。
- 单文件方法委托给批量方法，避免两套实现逐渐产生语义差异。
- 前端 store 只在批量命令整体成功后刷新一次；空路径数组直接返回，不产生 IPC。
- 不改变文件选择、Diff 跟随和快捷键行为，本次仅压缩相同操作的数据流成本。

## 验证方式

1. 混合选择已修改与未跟踪文件批量暂存，确认所有文件进入 staged 且只调用一次命令 / 状态刷新。
2. 批量取消暂存多个文件，确认工作区内容保留、Index 恢复到 HEAD。
3. 在无首个提交的仓库批量取消暂存部分路径，确认只移除目标项且 Index 正常写盘。
4. 点击目录行暂存 / 取消暂存，确认所有后代文件一次完成且选择行为不变。
5. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
