# 性能与刷新一致性优化

## Context

只读排查确认了八类问题：Diff 的平方级索引查找及全量渲染、历史分页重复 revwalk、丢失引用的重复祖先扫描、同步 Git 工作占用异步线程、linked worktree 监听遗漏、刷新缩减历史分页、引用元数据比较不完整，以及工作区 diff 统计重复计算。

目标是逐项修复并分别提交，保持现有 Git 语义、默认偏好、分页与搜索范围、Diff 模式、键盘导航和文件 / Hunk 操作。已有虚拟滚动、防抖、请求过期保护和确认上下文校验继续生效。

## 关键决策

- 不以关闭丢失引用、减少搜索范围、隐藏统计或截断正常 Diff 来规避开销；优化内部计算、缓存及渲染。
- 引用比较显式覆盖领域类型字段，仍保留未变化时不赋值的响应式优化。
- 历史缓存以仓库和实际 Git 快照 / 过滤条件隔离，不单靠 watcher 通知判断有效性，避免漏事件后读到陈旧结果。
- Reflog tip 判定共用一次祖先访问集合，在已知可达提交处停止；只保留需要标记的 reflog 入口，不为每个入口重复扫描整段公共历史。
- 后端跨任务只传路径和可发送的数据；Git 仓库句柄在执行任务的线程内打开和使用。
- 大文件渲染必须保留完整数据的搜索、导航和复制能力；不能把 DOM 虚拟化变成功能裁剪。
- 如需变更 IPC，同步更新 `docs/11-ipc.md`；设计文档只记录契约与取舍，不复制实现。

## 验证方式

每次代码提交前执行 `cargo fmt`、`npx vue-tsc --noEmit`、`npm run test`、`cargo check` 和 `cargo test`。前端当前没有格式化脚本，不新增格式化工具。

端到端路径：打开普通仓库与 linked worktree，浏览多页历史后切换窗口 / 手动刷新；外部修改 upstream、重建同提交标签、创建分支与暂存文件；检查界面同步且浏览位置稳定。打开大文本文件，在 inline / side-by-side、分块 / 完整文件、换行和高亮状态之间切换，搜索屏幕外文本并执行变更跳转、复制和 Hunk 操作。对有大量提交与失联 reflog 条目的临时仓库重复分页，比较扫描量与耗时；并发慢任务时验证其他 IPC 仍可响应。

基线：前端 530 个测试、后端 138 个测试及类型 / 编译检查通过。临时一万提交仓库的调试构建中，每页 200 条累计读取约 27.6 秒，直接引擎一次读取约 0.54 秒；100 个失联提交使首屏读取从约 0.48 秒增加到 2.80 秒。该数据仅作本机后端对照，不代表 WebView 端到端耗时。
