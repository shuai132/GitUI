# 可恢复的丢弃改动并切换分支

## Context

GitUI 已在脏工作区切换分支时提供“携带改动”与“Stash 后切换”，但本地分支右键菜单仍保留一个独立的“强制切换”入口。该入口直接执行 force checkout，会覆盖未提交改动，既绕过统一的分支切换引导，也绕过工作区丢弃操作已有的系统废纸篓保护。

GitHub Desktop 的官方分支管理流程会在脏工作区切换时要求用户明确选择改动去向；其丢弃流程则会把普通文件保存在系统废纸篓。预期结果：把“丢弃改动并切换”纳入同一个选择框，先复用可恢复丢弃流程，再执行 safe checkout；移除不可恢复的强制切换旁路。

## 关键决策

- 三种选择都只在工作区存在 staged、unstaged 或 untracked 项时出现；clean 工作区仍一步完成切换。
- “丢弃改动并切换”先调用工作区现有的批量丢弃流程：普通文件原内容进入系统废纸篓，submodule 仅恢复 Git 状态且明确不承诺可从废纸篓恢复。
- 丢弃完成后仍执行 safe checkout，不把 force checkout 包装成新的按钮；若目标分支仍因 ignored 文件或其他原因无法检出，保持对话框打开并允许重试。
- 丢弃成功但切换失败时记录中间状态，重试只执行切换，避免重复创建废纸篓副本或覆盖用户随后恢复的内容。
- 移除 UI 中的强制切换入口；后端 `force` 参数暂不删除，避免把安全交互优化扩大为 IPC 契约变更。
- 创建新分支并立即切换的现有行为不变。

## 验证方式

1. 在 clean 工作区切换分支，确认不弹窗且使用 safe checkout。
2. 在脏工作区打开分支切换对话框，确认可选择携带、Stash 或丢弃后切换。
3. 选择丢弃后切换，确认普通文件原内容进入系统废纸篓，目标分支切换成功且工作区立即刷新。
4. 模拟丢弃失败，确认不执行分支切换、对话框保持可操作并显示明确错误。
5. 模拟丢弃成功但 safe checkout 失败，确认提示内容已在废纸篓、重试不会再次丢弃。
6. 确认本地分支右键菜单不再出现“强制切换”。
7. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
