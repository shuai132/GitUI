# Confirm Repository GC

## Context

Actions 菜单当前点击“清理仓库 (git gc)”后立即执行。`git gc` 虽是常规维护，但会按仓库配置过期 reflog 和清理不可达对象，可能缩短误删提交的恢复窗口。目标是在运行前展示应用内确认，明确目标仓库与影响，并冻结 repoId，避免菜单打开后切换仓库造成误操作。

## 关键决策

- 使用危险样式确认，因为结果可能降低 Reflog / 不达对象的可恢复性；不把它描述成普通的无副作用性能优化。
- 确认文案说明行为受仓库 Git 配置控制，不承诺固定过期天数。
- 请求只携带捕获的 repoId；确认前 active repo 变化则取消，开始执行后允许原仓库维护完成。
- 不改 `run_gc` IPC 与 Git 参数，本轮只收紧用户触发边界。

## 验证方式

- 点击菜单后确认 IPC 尚未调用，且对话框显示目标仓库和恢复窗口警告。
- 确认后只对捕获仓库调用 `run_gc`，loading 期间禁止重复确认和取消。
- 对话框打开后切换仓库再确认，确认旧请求被取消且不调用 IPC。
- 运行目标 Vitest、`npx vue-tsc --noEmit`、`npm run test`、`cargo fmt`、`cargo check`、`cargo test`。
