# 双击工作区文件打开编辑器

## Context

GitUI 工作区文件已经支持右键“在编辑器中打开”，但双击文件行只重复执行单击选择，用户从 Diff 发现问题后要修改文件仍需打开菜单。这个动作无需新的 Git 能力，只缺少高频手势入口。

[GitHub 官方 Changelog](https://github.blog/changelog/2023-08-16-github-desktop-community-adds-check-out-a-commit-and-double-click-to-open-external-editor/)把“双击在外部编辑器打开”列为社区高度请求、已正式交付的 GitHub Desktop 改进。

本阶段把 WIP 普通文件双击映射到 GitUI 现有编辑器打开命令，并在文件悬停提示中说明手势。

## 关键决策

- 只处理普通文件；树形目录继续用单击展开 / 折叠，Submodule 继续使用专门的打开仓库动作。
- 删除状态没有可打开的工作区文件，因此不发出事件；不让必然失败的系统调用打扰用户。
- 行内暂存按钮阻止双击冒泡，避免连续点击按钮意外打开编辑器。
- 双击先保留既有单击选择行为，再执行打开动作；Diff 选择和多选语义不另设分支。
- 复用 `open_file_in_editor`，不新增 IPC。

## 验证方式

1. 双击未暂存或已暂存普通文件，确认系统编辑器打开工作区绝对路径。
2. 双击删除项、Submodule 或目录，确认不调用编辑器。
3. 双击行内暂存 / 取消暂存按钮，确认只执行按钮动作。
4. 单击选择、组合键多选、右键菜单和键盘审阅不回归。
5. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。

验证结果：前端 204 个、后端 76 个测试通过，TypeScript 类型检查和 Rust 编译检查通过。
