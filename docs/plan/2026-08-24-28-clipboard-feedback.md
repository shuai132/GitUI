# 统一文本复制反馈

## Context

仓库、分支、Remote、Tag、提交与文件菜单直接调用浏览器剪贴板；部分入口能在异常时显示通用错误，成功时都没有反馈，Reflog 与错误历史又各自重复实现了成功 / 失败 Toast。用户无法确认菜单是否已生效，剪贴板权限失败的处理也不一致。

预期结果：提供一个轻量的文本复制 composable，统一成功 Toast 与本地剪贴板异常提示；现有文本复制入口复用它。终端的 Ctrl-C / Ctrl-V 保持原生终端语义，不纳入本轮。

## 关键决策

- composable 只接收纯文本，可选传入专用成功 / 失败文案；默认使用统一双语文案。
- 成功显示短时 success Toast；失败调用 `useGlobalToast.showActionError`，不写入 Git 后端错误历史。
- 复制函数返回 boolean，调用方需要时可判断结果；默认不抛出已反馈的剪贴板异常。
- 不修改终端选择复制 / 粘贴，不在高频终端交互中增加 Toast。

## 验证方式

1. 模拟复制成功，确认写入完整文本并显示一次 success Toast。
2. 模拟浏览器拒绝剪贴板权限，确认显示一次非阻塞错误且 Promise 不外泄。
3. 从仓库、分支、Tag、提交和文件菜单触发复制，确认均复用公共入口。
4. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
