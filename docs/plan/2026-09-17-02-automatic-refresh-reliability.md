# 自动刷新可靠性修复

## Context

普通 Git 仓库在外部工具修改、提交后偶尔保留旧工作区状态。已用当前 watcher 复现：ignored 日志持续写入会不断推迟滑动防抖的截止时间，代码、引用和 rescan 信号都无法及时通知前端。前端事件回调还会并发启动刷新，缺少最后一轮的合并调度与失败恢复。

预期结果：持续文件事件期间也能有界地通知当前仓库；自动刷新串行执行并保留执行期间的新事件；重新聚焦与短暂读取失败可恢复状态。

## 关键决策

- 后端使用从首事件起算的固定合并窗口，后续事件不重置期限；仍合并路径、批量过滤，只发送包含有效路径或 rescan 的批次。这同时限定最大等待并消除 ignored 噪声对期限的影响，无需逐事件打开仓库。
- 到期检查先于从消息队列取下一条事件，防止队列一直非空时饥饿；保留每个窗口末尾的新事件供下一轮处理。
- 自动事件与窗口聚焦补偿进入同一前端队列；一轮包含工作区及必要的历史、分支、标签、stash、submodule 和当前 WIP Diff，积累的事件按数据域合并。
- 切仓库或卸载取消待处理事件和重试定时器，旧会话不能触发新会话的后续刷新。现有 store 请求序号保护继续保留。
- 工作区刷新返回明确结果，瞬时锁竞争等读取失败有限重试，永久错误不循环；原始 IPC 错误保留用于分类，错误历史与提示仍复用现有通路。
- 同一后端批次同时含配置与引用变化时使用保守分类，确保两类数据域都刷新；事件结构保持不变。
- 不新增 IPC，不引入周期性仓库轮询，不改手动 Refresh、历史算法、状态统计或用户设置默认值。
- 本次属于自动刷新 bugfix，根 README 的功能清单无需改变。

## 验证方式

- Rust 回归覆盖持续事件、ignored 噪声、持续队列、rescan、批次尾部事件和停止监听。
- 前端回归覆盖多事件合并、刷新中再次提交、配置与引用域同时变化、失败重试、切仓库与卸载、聚焦限频。
- 在临时普通仓库运行 watcher，持续写 ignored 文件的同时修改 tracked 文件并从外部提交，确认通知在噪声停止前到达；只有 ignored 写入时不触发前端刷新。
- 用含数千提交和文件的临时仓库验证事件派发与过滤频率，前端用延迟请求验证无并发自动刷新堆积。
- `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo fmt`、`cargo check`、`cargo test`。

## 验证结果

- TypeScript 类型检查和 Rust 编译检查通过；前端全量 530 个测试、后端全量 138 个测试通过。
- 已执行 `cargo fmt` 和 `git diff --check`；仓库未配置前端格式化器，沿用已有代码风格。
- 在系统临时目录创建含 5,000 个 tracked 文件、5,000 次提交的普通仓库，使用当前 watcher 源码和真实 macOS 文件事件验证。ignored 日志持续写入期间，通过外部 Git 提交修改；从编辑开始约 470ms 收到包含提交引用的通知，全程只有两个有效批次，纯 ignored 写入未产生通知。
- 同一临时仓库对 ignored 批次做 100 次过滤，平均约 6.2ms。该值仅用于确认此次批量过滤开销，不代表完整 Refresh 耗时。
- 前端用可控延迟 IPC 验证提交期间的末尾补刷、各域合并、失败恢复和旧会话隔离；未进行完整桌面窗口的端到端交互测试。
