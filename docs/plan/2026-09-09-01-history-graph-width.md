# 提交图列宽约束与拖动调整

## Context

当前 `HistoryView` 根据所有已加载提交的最大泳道数确定图宽。分支多时，图会把描述等数据列推到很远，分页也可能改变列的位置。需要给提交图一个稳定、可调整的显示范围，让提交信息始终从明确的边界开始。

## 关键决策

- 图列使用独立持久化宽度，默认适中；分页、滚动和切换仓库不会随泳道数量推移数据列。用户可以拖动图右侧（默认位于描述左侧）的分隔线扩大或缩小显示范围。
- 复用现有图列的 CSS 裁剪，将超出的线条限制在图形区域。效果与数据列覆盖图层一致，同时保留透明高亮、主题和拖拽反馈的现有语义，无需给每个数据列叠加不透明背景。
- 图的泳道位置、连接关系、SVG 绘制与虚拟滚动保持现有机制；不挤压泳道或重新布局 DAG。超出显示范围的节点可能不可见，扩大图宽可查看更多泳道。
- 图宽调整只更新布局，拖动结束后才写入本地偏好，不触发 Git IPC 或重算提交图；不新增后端契约。

## 验证方式

- 单元测试验证旧偏好补齐、图宽边界、表头事件、列排序与拖动清理。
- 在大批量多泳道提交场景中检查描述起点固定、超宽 SVG 不扩张滚动区域；拖动后表头、提交行和 WIP 对齐，并检查选中、高亮与横向滚动。
- 执行 `npx vue-tsc --noEmit`、`npm run test`、`cargo check` 和 `cargo test`。

## 验证结果

- 前端类型检查与 Rust 编译检查通过；前端 464 个测试、后端 135 个测试全部通过。
- 创建包含 10000 次提交、65 个分支的临时 Git 仓库，将真实日志载入 `HistoryView` 浏览器验证页；后端 IPC 使用测试替身，验证范围为前端布局和交互。
- 64 泳道产生的 896px SVG 被限制在设定图宽内，没有撑大列表；拖动上下限、重载恢复、表头与 WIP 对齐、列排序、横向滚动、浅色 / 深色主题和选中行显示均通过。
- 全高列表滚动时只挂载约 40–44 行；调整图宽期间 IPC 计数保持不变。临时验证页面与仓库验证后移除，不纳入项目。
