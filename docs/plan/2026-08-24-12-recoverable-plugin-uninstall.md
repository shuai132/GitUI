# 可确认、可恢复地卸载插件

## Context

插件设置页的删除按钮当前立即调用 `uninstall_plugin`，后端直接递归删除应用数据目录中的插件副本。用户看不到将被删除的插件 ID、版本与路径，也没有机会取消；误点后只能重新从原始目录安装。VS Code 与 JetBrains 都把 Disable 与 Uninstall 作为不同生命周期动作，GitUI 也已提供禁用入口，因此永久卸载应具有更明确的目标与恢复路径。

预期结果：卸载前用应用内危险确认展示插件名称、版本、ID 与安装路径；确认期间插件被刷新或替换时取消旧请求；后端把安装副本移入系统废纸篓，再清理启用状态，使误卸载可从废纸篓恢复。

## 关键决策

- 只移动 GitUI 应用数据目录中的已安装副本；用户最初选择的源目录不受影响。
- 目录成功进入系统废纸篓后才移除插件启用状态；移动失败则命令失败，不继续写状态。
- UI 捕获插件 ID、名称、版本与安装路径，并在执行前和当前 store 条目精确比对，避免刷新后旧确认作用到替换版本。
- 保留既有 `uninstall_plugin` IPC 名称与成功返回类型，仅收紧其删除语义。

## 验证方式

1. 点击卸载，确认框显示精确插件身份与安装路径；取消后不调用 IPC。
2. 确认期间刷新 / 替换同 ID 插件，旧确认取消并提示重新选择。
3. 确认卸载后插件副本进入系统废纸篓，列表移除且源目录仍存在。
4. 模拟废纸篓移动失败，确认插件目录和状态不变。
5. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
