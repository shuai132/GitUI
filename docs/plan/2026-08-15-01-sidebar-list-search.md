# 侧边栏列表搜索

## Context

仓库包含大量本地分支、远程分支、Tag 或 Submodule 时，侧边栏只能依赖滚动和树节点逐层展开定位，查找成本较高。为侧边栏中的集合型区域提供一致的放大镜搜索入口，让用户可以按名称或路径即时缩小结果范围，同时保留现有点击、右键和拖动等操作。

预期结果：本地分支、Tag、Stash、Submodule、远程分支和“所有仓库”区域均可从标题栏打开紧凑搜索框；树形分支的命中路径在搜索期间自动展开，清空搜索后恢复原有树形展示和折叠状态。

## 关键决策

- 搜索状态仅保存在对应组件内，不跨仓库持久化，避免切换仓库后残留筛选造成内容“消失”。
- 匹配不区分大小写；分支与 Tag 按完整名称匹配，Submodule 和仓库同时匹配名称、路径及可用 URL，Stash 同时匹配序号和消息。
- 搜索只过滤前端已经加载的数据，不增加 IPC、后台扫描或额外网络请求，因此不会改变现有刷新链路和热路径成本。
- 分支搜索沿用原树形结构，但搜索期间忽略节点折叠状态；清空后继续使用用户原有的折叠状态。
- “所有仓库”搜索期间禁用拖动排序，避免过滤后的视觉序号与底层完整列表序号不一致。

## 验证方式

1. 在包含多层本地/远程分支、大量 Tag、Stash、Submodule 和多个仓库的环境中，逐个点击标题栏放大镜并输入大小写混合的部分名称。
2. 确认仅显示命中项；分支的父目录可见且自动展开；清空或按 Escape 后恢复完整列表和原折叠状态。
3. 确认筛选结果仍可点击、双击和打开右键菜单；所有仓库清空筛选后仍可拖动排序。
4. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
