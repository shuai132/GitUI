# 保护本地与远端 Tag 删除目标

## Context

GitUI 的 Tag 删除确认只捕获标签名。本地 Tag 在确认期间被外部命令重建时，确认仍会删除新对象；删除远端 Tag 也在确认后才选择 remote，用户确认时看不到实际 remote 和对象。勾选“同时删除远端”时当前顺序更是先删除本地，再打开 remote 选择：取消 remote 或远端失败会留下与用户选择不一致的半完成结果。

GitLab 通过 Protected Tags 防止意外更新或删除，且删除受保护 Tag 的 UI 要求明确确认标签名。预期结果：本地与远端删除都捕获精确 ref OID；远端删除在确认前完成 remote 选择与目标预览；组合删除先验证全部目标并先完成远端操作，避免远端失败时提前丢失本地引用。

## 关键决策

- 本地与远端命令都接受可选 expected OID；前端所有侧边栏删除入口传入确认时捕获的精确 `ref_oid`。
- 单独删除远端 Tag 时先选择 remote 并读取该 remote 的 Tag 列表，再打开确认框。确认内容包含标签名、remote 和短 OID。
- 组合删除保留一个确认框和“同时删除远端”复选框；用户确认后若勾选，先选择 remote、读取并验证目标。取消选择或目标不存在视为整个组合操作取消，不退化为只删本地。
- 组合删除执行顺序为远端后本地：远端失败时本地保持；远端成功但本地因极短窗口发生变化时，后端拒绝删除新本地 Tag，用户仍可单独处理本地。
- 远端删除复核消除陈旧确认窗口，但与强推保护相同，不宣称协议层原子 lease。
- 不为“远端同步”联合状态猜测具体 remote；用户必须明确选择目标 remote。

## 验证方式

1. 删除本地 Tag，确认请求携带该 Tag 的 `ref_oid`；确认期间重建同名 Tag 时拒绝删除。
2. 单独删除远端 Tag，确认框显示 selected remote、Tag 与短 OID；取消时不执行。
3. 组合删除勾选远端后取消 remote picker，确认本地与远端均不删除。
4. 组合删除远端失败，确认本地 Tag 保留；成功时调用顺序为远端后本地。
5. 确认后远端目标变化，确认后端拒绝删除新对象。
6. 运行 `npx vue-tsc --noEmit`、`npm run test`、`cd src-tauri && cargo check`、`cd src-tauri && cargo test`。
