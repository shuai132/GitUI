# Guarded Conflict Resolution

## Context

冲突编辑器与工作区右键操作目前只携带文件路径：store 在异步完成时重新读取 active repo，缓存也仅按路径区分；后端保存内容或选择 ours / theirs 前不复核 index 中的三方冲突条目。多仓库切换、慢加载返回或外部工具先一步解决 / 改变冲突时，旧操作可能覆盖新上下文。目标是把读取、预览和解决动作绑定到仓库及精确的 index 冲突身份。

## 关键决策

- 冲突上下文标识是由 base / ours / theirs 的 blob OID 与 mode 组成的后端生成字符串；前端只透传，不解析。
- 删除 / 修改、添加 / 添加等缺侧冲突同样编码 `None`，避免把缺失侧误当成空文件。
- 保存合成内容与选择 ours / theirs 共用同一预期标识；目标已被外部解决或替换时拒绝，不把普通文件重新 stage 为“已解决”。
- 前端缓存 key 包含 repoId；慢请求只有在 repoId、路径和请求序号仍匹配时才进入当前编辑器。

## 验证方式

- 打开冲突编辑器后切换仓库或文件，延迟返回旧请求，确认不覆盖新预览且不能保存到新仓库。
- 外部解决冲突或改变 index 三方条目后，从旧编辑器保存 / 选择某侧，确认后端拒绝且工作区文件不变。
- 正常文本冲突保存、二进制冲突选择 ours / theirs 仍能完成，并只刷新目标仓库。
- 运行目标 Vitest / Rust 测试、`npx vue-tsc --noEmit`、`npm run test`、`cargo fmt`、`cargo check`、`cargo test`。
