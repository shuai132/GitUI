# 删除远端已不存在的分支时清理本地引用

## Context

服务器已删除分支而本地仍有跟踪引用时，带明确 lease 的删除请求会被拒绝。界面把拒绝泛化为他人推送新提交，用户无法通过删除操作清理残留节点。

目标：删除请求失败后，只有成功核实推送目标上已无该分支，才清理用户确认的本地跟踪引用；真实目标变化和网络 / 认证失败仍保留引用并报错。

## 关键决策

- 正常删除继续使用明确 OID 的 force-with-lease；仅失败路径增加远端查询，不增加刷新热路径负担。
- 核查 fetch URL 与实际 push URL（包含独立 push URL 和多个推送目标）；任何目标仍有分支或查询失败均不按缺失处理，避免独立推送地址掩盖抓取端仍存在的分支。
- 清理仅限用户选择的本地跟踪引用，锁定后复核 OID；不 prune 其他分支，不删除本地工作分支。
- 查询确认的是当时远端状态，不绕过 lease 重试删除后来重新创建的服务器分支。
- 使用临时仓库验证，不向用户的真实远端发删除请求。

## 验证方式

临时 bare 仓库覆盖正常删除、远端缺失、远端 OID 变化、本地 OID 变化、独立 push URL 与查询失败。运行项目四项检查，确认成功后沿用现有 store 刷新流程移除树节点。
