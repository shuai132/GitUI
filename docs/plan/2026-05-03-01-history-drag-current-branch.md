# History Drag Current Branch Semantics

## Context

历史视图支持把一个提交拖到另一个提交后选择 Merge 或 Rebase。当前实现记录了拖拽提交和放置提交，但实际 Git 操作仍作用在当前检出的 HEAD 分支上。用户容易把 `a` 拖到 `b` 理解为“把 a 所在分支合入 b 所在分支”，尤其当前分支是第三个分支 `c` 时风险更高。

预期结果：拖拽弹窗明确表达所有操作都作用于当前分支；不自动切换分支、不自动创建本地跟踪分支。

## 关键决策

- 做：拖拽动作只操作当前检出的 HEAD 分支，弹窗必须显式展示当前分支。
- 做：合并来源允许本地或远程分支 tip；远程分支不要求先创建本地分支。
- 不做：`a` 合入 `b` 的跨分支直接集成。该模型需要额外处理 checkout、脏工作区、远程目标本地化和确认流程，暂不纳入本次改动。
- 不做：自动检出目标分支或自动创建本地跟踪分支，避免隐藏副作用。

## 验证方式

- 前端单测覆盖远程分支 tip、非分支 tip、当前分支 tip、detached HEAD 和目标为 HEAD 的禁用规则。
