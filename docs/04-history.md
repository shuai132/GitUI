# 04. 提交历史视图

历史视图是系统的核心，集成了提交图、日志列表、变更详情以及工作区入口。它旨在提供一个统一的界面来浏览版本演进并执行版本管理动作。

## 核心职责

- **版本溯源**：通过提交图与列表展示版本演进脉络，支持分页加载海量日志。
- **提交过滤**：支持基于文本、作者及哈希值的实时搜索与过滤。
- **关联展示**：展示分支标签、标签（Tags）以及远程同步状态。
- **详情透视**：提供提交元数据（作者、日期、完整信息）与文件差异的深度查看。

## 视图布局与交互

### 灵活布局
支持水平（左右）与垂直（上下）两种布局模式，满足不同屏幕尺寸下的查看习惯。所有面板大小与列宽均支持交互式调整并自动持久化。

### 虚拟滚动与分页
利用虚拟滚动技术确保在大仓库下的流畅滚动，并采用自动分页策略在用户接近底部时加载更多历史。

打开或切换仓库后，历史视图保持默认全量图，但会在初始数据加载完成后自动把当前 HEAD 滚入视野。若 HEAD 不在第一页，前端会沿用分页加载继续补页直到找到目标或到达日志末尾；该定位只滚动列表，不选中提交，也不打开详情面板。当前 HEAD 行使用轻量底色和左侧细线标识，区别于真正选中的提交行。

历史列表的数据列（描述、变更、提交、作者、日期）支持通过列头拖拽调整顺序，并持久化为全局 UI 偏好；提交图列和面板拖拽手柄保持固定。列宽仍按列本身持久化，调整顺序不会改变既有宽度。

历史列表包含默认隐藏、可在设置页「高级 / 视图」或工具栏「更多操作」菜单中手动开启的「变更」列，用于快速识别提交规模：展示变更文件数、增删行数，并对二进制文件和大文件提交显示简短 badge。该统计不随 `get_log` 返回，而是由前端在「变更」列显示时，根据虚拟列表当前可见提交批量调用 `get_commit_change_stats` 懒加载并缓存，避免拖慢历史首屏和分页热路径；默认隐藏可避免大仓库滚动时持续触发统计计算。WIP 行同列展示当前工作区文件数与行级统计。

### 键盘导航
提供完整的键盘快捷键支持，允许用户在提交列表与文件清单间快速切换、移动选中项并触发常用动作。设置页中的「选中上一个/下一个提交」快捷键通过 `history` store 写入 `pendingJumpOid`，由 `HistoryView` 统一负责补页、选中和滚动定位，避免绕过虚拟列表。

## 数据集成逻辑

### 日志构建 (Revwalk)
后端采用启发式算法构造提交序列：
- **可达性分析**：仅在开启“显示丢失引用”时构建引用可达集合，用于区分已引用提交、丢失引用的提交（Unreachable）以及贮藏（Stash）；普通历史加载跳过这一步以保持首屏轻量。
- **结构化转换**：将 Git 内部的提交关系转换为前端易于渲染的平铺列表，并为提交图算法提供必要的拓扑信息。
- **辅助过滤**：在渲染时智能过滤掉 Git 内部的辅助提交（如 Stash 产生的索引/未追踪快照），保持视图整洁。

### 变更规模统计
`get_commit_change_stats` 按提交 first parent 计算文件数、增删行、二进制文件数和大文件指标。Root commit 对空树统计；stash 沿用提交详情语义，额外补上 untracked parent。前端以 OID 为 key 缓存结果，切换仓库时清空缓存。

### 搜索与过滤
系统在前端实现实时的文本过滤，支持匹配标题、作者及 OID。在搜索模式下，系统会动态调整视图（如隐藏提交图）以优化信息密度。

历史日志还支持两个持久化的图过滤偏好：
- **Solo 当前分支**：`ui` store 按仓库 path 保存 `HistoryBranchScope`；active repo 的 scope 为 `current_first_parent` 时，`get_log` 只从当前 HEAD 出发并按 first-parent 链构建日志，用于查看更干净的当前主线。
- **显示远程分支**：`showRemoteBranches` 控制远程分支是否作为 `get_log` 的日志来源；关闭时提交行也不显示远程分支 chip。

每个仓库的 Solo 默认值都是 `all`，不会从其他仓库继承；关闭仓库不会清理同一路径的 Solo 偏好。远程分支显示仍是全局视图偏好，默认值为 `showRemoteBranches=true`。

`Solo 当前分支` 的语义是 first-parent 主线视图，不是“当前分支可达的所有提交”。被合并进来的 side branch 具体提交会被隐藏，只保留沿 HEAD first-parent 链可见的历史，用于降低合并分支带来的图噪音。

### 标签与同步状态
- **分支/标签映射**：动态计算并展示指向特定提交的所有引用。
- **远程同步感知**：通过后台比对，为标签提供远程同步状态指示（如已同步、仅本地等）。
- **远程分支可见性**：远程分支 chip 跟随 `showRemoteBranches`，本地分支与 tag chip 不受影响。

## 详情面板功能

### 元数据查看 (CommitInfo)
展示详尽的提交信息，支持长内容的横向滚动与文本的自由选中复制。文件变更列表支持按路径搜索并能关联到 Diff 查看器。

提交详情的变更文件右键菜单支持复制路径、在文件系统 / 编辑器中打开、签出该文件历史版本，以及进入 File History / Blame。File History / Blame 弹窗按当前 repoId 与文件路径隔离提交列表、Diff 和 Blame 请求；打开期间切换仓库或目标路径会立即清空旧内容并加载新上下文，较晚返回的旧请求不能覆盖当前结果。列表视图下，文件还可被移到最前 / 最后，或恢复默认位置；该排序偏好按仓库路径独立保存，并复用到工作区变更文件列表。树形视图保持目录结构与字母序，不提供排序动作。若变更路径对应当前仓库的 direct submodule，菜单会提供打开该 submodule 仓库的动作；未初始化或工作区不存在时，菜单改为提供 init / update 动作。历史 diff 会保留文件 mode，用于把当前工作区已不存在的旧 submodule gitlink 仍标记为 submodule 项；这类旧项只做识别，不提供当前工作区动作。

### 差异对比
集成三模态 Diff 查看器，详情见 `docs/06-diff-viewer.md`。

## 版本管理动作

通过上下文菜单提供丰富的管理能力：
- **分支管理**：基于特定提交创建分支或标签。创建表单冻结打开时的仓库和提交目标；多仓库切换不会把旧输入应用到新仓库，切回原仓库后可继续。
- **引用变更**：检出提交、重置分支（Soft/Mixed/Hard）。若提交行显示远程分支 chip，右键菜单提供 `检出: <remote>/<branch>` 和复制分支名动作；检出动作复用远程分支检出流程创建本地跟踪分支。
- **内容迁移**：Cherry-pick、Revert。
- **信息修补**：支持对 HEAD 或历史提交进行消息修补（Reword）。修改提交信息对话框可同时编辑作者信息、作者时间与提交时间，并提供在作者时间和提交时间之间双向复制的快捷按钮。HEAD Reword 保存打开时的 repoId、HEAD OID 与完整 ref，后端写入前再次复核；历史提交继续走绑定同一上下文的交互式 Rebase。

Checkout、Cherry-pick、Revert、Reset 和删除历史图 Stash 使用统一的应用内确认框，不依赖 WebView 原生对话框。确认内容展示提交摘要、短 SHA 以及分支 / Reset 模式或 Stash 消息；Hard Reset 和删除 Stash 使用危险按钮。挂起请求保存仓库、HEAD OID / 分支 ref 与目标提交快照，后端执行前再次校验；上下文变化时取消旧请求，避免较晚确认落到另一段历史。

提交行 hover tooltip 与右键菜单互斥：打开右键菜单时会立即隐藏 tooltip，且菜单可见期间不会重新展示。菜单打开后左键点击外部区域只负责关闭菜单，不透传为底层行选中或按钮点击；右键点击其他目标仍可切换到对应目标的上下文菜单。

## 刷新策略

任何导致引用变动的操作（如切换分支、重置、Cherry-pick）都会触发自动的日志与分支状态刷新，确保 UI 与底层仓库状态实时同步。

普通刷新不会重复执行初始 HEAD 定位，避免用户浏览历史时被强行拉回当前分支。
