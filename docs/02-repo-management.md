# 02. 多仓库管理

GitUI 支持多仓库同时挂载与快速切换。本中心模块负责仓库的生命周期管理、状态持久化以及多实例协作。

## 核心职责

- **名册管理**：维护已打开仓库的路径映射与唯一标识。
- **生命周期**：处理仓库的打开、克隆、初始化及关闭。
- **状态监控**：管理当前激活仓库的文件系统监听器，并协调防抖与过滤逻辑。
- **持久化**：确保用户打开的仓库列表及最后活跃仓库在重启后能正确恢复。

## 仓库操作流程

### 创建与克隆
- **统一入口**：通过前端 Store 协调创建逻辑，确保无论是 Clone 还是 Init，最终都收敛到统一的仓库注册流程。
- **后台执行**：长耗时的 Git 操作在后端异步执行，并通过事件流实时回传进度信息。
- **进阶处理**：Clone 过程中支持凭据回调映射、递归子模块以及浅克隆配置。
- **目标目录偏好**：Clone 对话框记住最近选择或填写的父目录并在下次预填；清空目录会删除该偏好。URL、自定义名称、深度和递归 Submodule 等一次性参数仍在每次打开时重置。

### 打开与激活
- **验证**：打开路径时由后端验证其 Git 有效性。
- **名册注册**：成功验证后分配唯一 ID；文件监控服务只在仓库被激活时启动。
- **激活链**：仓库激活后，会自动触发前端各 Store（工作区、历史、分支、子模块等）的刷新逻辑。
- **恢复失败**：启动时暂时无法打开的持久化路径保留为前端不可用项，不注册到后端，也不参与 watcher / fetch；原路径恢复后可重试，目录移动后可重新定位，只有用户显式移除才从名册删除。

## 状态持久化机制

系统区分两类持久化数据：
1. **名册数据**：存储在独立的配置文件中，包含已打开仓库的路径列表及活跃路径，由插件化存储引擎管理。
2. **UI 偏好**：存储在前端本地缓存中，包含侧栏宽度、面板高度、显示偏好等非核心业务数据。

## 切换与视图状态恢复

为保证无缝切换体验，系统实现了以下机制：
- **状态快照**：切换仓库时，当前仓库的视图状态（如选中提交、滚动位置、工作区缓存）会被记录。
- **多 Session 隔离**：如内置终端等模块，会为每个仓库维护独立的进程 Session，确保切换回来时状态保持。
- **延迟加载**：非活跃仓库仅保留基础路径信息和前端视图缓存，不保留后端文件系统 watcher；只有在切换激活时才发起完整的元数据加载。

## 所有仓库列表

- **名册顺序**：底层仓库名册仍保持用户打开 / 拖拽后的顺序，并按路径持久化。
- **目录拖入**：“所有仓库”区域在 0、1、多个仓库时始终可见，可接收从 Finder / 文件资源管理器拖入的一个或多个 Git 仓库目录。命中区域会按窗口 DPI 将 Tauri 的物理坐标换算为 WebView 逻辑坐标并显示反馈；批量拖入逐项校验，单个无效目录不阻断其他项，完成后只激活最后一个成功仓库，避免中间仓库触发无意义的全域刷新。
- **即时搜索与快速切换**：悬停“所有仓库”区域时，标题栏显示放大镜，可按仓库名称或绝对路径过滤当前名册；全局“快速切换仓库”快捷键会自动展开侧边栏并聚焦同一搜索框，方向键循环选择、Enter 激活、Escape 退出。匹配到 Submodule 子仓库时保留父仓库作为层级上下文，但键盘候选只包含真正匹配的仓库；筛选期间暂停拖动排序，清空后恢复。
- **同名消歧**：只有多个仓库的本地目录名完全相同时，仓库行才追加最短可区分的父路径片段；普通仓库保持单行名称，完整绝对路径继续作为悬停提示。消歧由当前名册即时计算，不进入持久化数据。
- **不可用仓库**：恢复失败项显示最后目录名和不可用标记，悬停可查看最后路径与错误；点击行或重试按钮按原路径重开，Locate 选择替代目录后成功替换并激活，移除按钮才永久删除该记录。名称与路径搜索同样覆盖这些项。
- **添加入口**：侧边栏的添加仓库入口归属于“所有仓库”标题，用于打开本地仓库、Clone 远端仓库或 Init 新仓库。
- **Worktree 创建**：仓库行右键菜单提供“新建 Worktree”入口。前端读取该仓库的本地 / 远程分支作为起点，用户输入新本地分支与目标目录；后端创建 linked worktree 后返回路径，前端复用 `openRepo` 注册、持久化并激活新 worktree。
- **Submodule 层级**：如果已打开仓库 B 是已打开仓库 A 的 direct submodule，侧边栏“所有仓库”会把 B 缩进显示在 A 下方。关系由现有 `list_submodules` 数据和仓库工作区绝对路径匹配得到，不递归扫描未打开仓库。
- **操作一致性**：父仓库与子仓库行都保留原有点击激活、右键复制名称 / 复制绝对路径 / 新窗口 / Finder / 终端 / 新建 Worktree 和移除入口；树形展示只影响视觉归属，不改变 RepoManager 的注册模型。

## 文件系统监控 (Watcher)

- **激活仓库独占**：同一窗口内只监听当前激活仓库；切换仓库时后端停止旧 watcher 并启动新 watcher，无激活仓库时停止所有 watcher。
- **全工作目录监控**：激活仓库的监控范围覆盖整个工作目录以确保感知所有变动。
- **智能过滤**：后端在推送变动事件前，会按 Git ignore 规则过滤未跟踪路径（包含 `.gitignore`、`.git/info/exclude`、`core.excludesFile` 等来源），避免无效的 IPC 压力；已跟踪文件和 `.git/` 内部事件始终放行，防止漏刷新。
- **事件分类**：`repo://status-changed` 会携带 `kind`，区分普通工作区、Index、引用、配置和保守兜底的 `.git` 变动；前端据此只刷新必要的数据域。由于外部 Git 操作产生的文件系统事件可能被系统 watcher 合并成不完整批次，后端会把 rescan / 无路径批次保守归类为 `other_git`，确保前端重新读取真实状态；前端也会在刷新 `WorkspaceStatus` 后用 HEAD 快照兜底判断，只要 HEAD 已变化，即使本次事件被归类为工作区或 Index 变动，也会刷新历史、分支、标签和 stash。
- **防抖逻辑**：多文件连续变动会被合并为单个更新事件，平衡实时性与性能。

## 多实例协作 (macOS)

- **独立进程**：支持在新进程中打开仓库，实现窗口间的 Git 状态、文件监听和内置终端隔离。
- **启动握手**：通过命令行参数与 Managed State 协调，确保新实例启动后能自动激活目标仓库。
- **单一托盘 owner**：所有 GitUI 进程通过 app data 下的 owner lock file 选出唯一 `TrayCoordinator` owner。owner 绑定 loopback TCP listener，并把端口和随机 token 写入 owner state；非 owner 进程保持一条本地连接注册自己的 `window_id`、pid 和当前 active repo。
- **存活窗口 registry**：托盘菜单只由 owner 的 registry 驱动，仅列出仍有存活窗口且该窗口有 active repo 的仓库。registry 连接断开即清理对应窗口；同名仓库菜单项显示为 `name - path` 以消歧。
- **跨进程唤起**：托盘仓库项使用 `window:<window_id>` 作为菜单 id。点击 owner 本窗口时直接显示并聚焦；点击其他进程窗口时通过持久连接发送 `ShowWindow`。托盘左键和 Dock Reopen 优先唤起最近活跃的存活仓库窗口。
- **owner 接管**：owner 崩溃或退出时，存活客户端重新参与选主，获得锁的进程接管托盘。TCP 只绑定 `127.0.0.1`，消息必须匹配 owner state 中的 token。

## 界面定制

系统支持高度自定义的布局调整，包括侧栏宽度、列表高度等。侧栏宽度可以通过拖动分割条调整，也可以通过仓库标题区的收起按钮或双击分割条隐藏到左侧；隐藏后保留左侧边缘分割条用于重新展开。所有拖动类操作均遵循“交互中响应、动作结束后持久化”的原则。

顶部工具栏作为 Tauri overlay 标题栏的拖动区域使用。macOS 普通窗口下左侧会为系统红黄绿窗口按钮预留空间；进入原生全屏后系统按钮不占用标题栏区域，工具栏恢复普通左边距。Windows 与 Linux 保持默认工具栏边距。

顶部工具栏在系统终端按钮右侧提供手动刷新入口，用于在文件监听或外部同步未及时反映时重新加载当前激活仓库的前端状态。该入口复用全局“刷新仓库”快捷键语义，只针对当前激活仓库生效。

关闭窗口时按托盘 owner 状态分支处理：非 owner 窗口注销 registry、停止 watcher / auto-fetch 后退出；owner 窗口关闭时如果还有其他窗口存活，则阻止关闭并隐藏本窗口，停止本进程 watcher / auto-fetch，但保留 owner 进程继续托管原托盘；如果没有其他窗口则清理 coordinator 后退出。逻辑已关闭的 owner 窗口不会被 Dock Reopen 或托盘“显示窗口”重新显示，唤起会优先转发给存活客户端窗口。macOS 托盘图标使用独立 template 资源，由系统根据菜单栏状态自动着色；Windows / Linux 继续使用应用默认图标。
