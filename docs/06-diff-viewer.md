# 06. Diff 查看器

Diff 查看器服务于 **WIP 工作区 diff** 和 **提交内 diff**。两种场景共享同一套后端数据契约和前端渲染组件。

## 核心职责

- **数据获取**：根据当前仓库路径、文件路径、是否已暂存或特定提交 OID，计算并返回结构化的差异数据。
- **多模式展示**：支持左右分栏（Side-by-Side）和行内（Inline）两种布局，并提供独立的按 Hunk 分组选项。关闭分组时用完整文件上下文阅读，开启分组时用变更块聚焦阅读。PDF / DOCX / PPTX 文件进入文档预览分支，基于可提取文本展示内容 diff。
- **交互功能**：支持语法高亮、忽略空白变更、变更块快速跳转、图片/SVG 预览。
- **提交回滚**：提交 diff 可按 Hunk 反向应用到工作区；该入口只在开启按 Hunk 分组时展示，完整文件上下文模式不显示 Hunk 回滚操作。
- **WIP 区块操作**：工作区 diff 可在按 Hunk 分组时对单个 Hunk 执行暂存、取消暂存或放弃；暂存 / 取消暂存操作目标是 Index，放弃操作会按当前暂存侧决定是否同时改写工作区和 Index。
- **失败反馈**：提交回滚和 WIP 区块操作失败时进入统一错误 Toast / 历史，不只记录到开发者控制台；用户可在刷新 Diff 后重试。

## 模块划分

- **后端 (`commands/diff.rs`)**：负责调用 Git 引擎获取差异。针对工作区 diff，会包含未追踪（Untracked）文件的内容。
- **前端组件 (`components/diff/`)**：
  - `DiffView`：主入口，负责图片 / SVG / 文本 diff 分流，并接线具体渲染组件。
  - `DiffToolbar`：承载布局切换、按 Hunk 分组、空白过滤、搜索入口、变更块跳转和 SVG 图片 / 文本切换。
  - `InlineDiff`：渲染行内流式布局；关闭分组时显示完整文件，开启分组时按 hunk 分块。
  - `SideBySideDiff`：渲染左右对比布局；关闭分组时处理完整文件行对齐，开启分组时只渲染 hunk 内容。
  - `ImageDiff`：处理位图和 SVG 的特殊对比展示。
  - `DocumentDiff`：处理 PDF / DOCX / PPTX 文档预览和抽取文本 diff。
- **前端逻辑 (`composables/diff/`)**：
  - `useDiffSearch`：管理 diff 搜索框状态，并响应全局搜索信号。
  - `useRevertHunk`：管理提交 diff 的 hunk 反向应用操作。
  - `useWipHunkAction`：管理工作区 diff 的 hunk 暂存 / 取消暂存 / 放弃操作。
- **逻辑工具 (`lib/highlight.ts`, `lib/wordDiff.ts`, `lib/fullFileDiff.ts`)**：提供语法高亮映射、词级差异计算和完整文件 diff 行构造。
  - `lib/hunkPatch.ts`：根据 `FileDiff` 与 Hunk 方向构造可应用的单 Hunk patch。

## 数据契约

后端返回的差异数据结构应包含以下关键信息（详情见 `src/types/git.ts::FileDiff`）：
- **文件路径**：旧路径与新路径（处理重命名）。
- **差异统计**：新增行数与删除行数。
- **Hunk 列表**：每个 Hunk 包含补丁头（Header）及具体的行数据。
- **Blob 引用**：旧版与新版的 Blob OID，用于按需拉取原始内容（如图片预览）。

关闭按 Hunk 分组时，Inline / Side-by-Side 不要求后端返回全量上下文；前端根据 Blob 引用和工作区读取接口按需加载完整旧 / 新文本，再用 hunk 元数据补齐未变化行。读取失败或超过原始内容读取阈值时，文本视图回退到后端 hunk 数据。

文档预览额外使用 `src/types/git.ts::DocumentTextSource` 和 `DocumentText`。前端按旧 / 新两侧构造 blob 或工作区来源，后端抽取 PDF / DOCX 文本后返回；该文本只用于文档内容 diff，不替代 `FileDiff` 的 hunk 契约。

## 关键特性实现策略

### 查看模式持久化
用户选择的布局模式和按 Hunk 分组开关会分别持久化到本地存储，以便在不同会话和仓库间保持一致。新用户默认使用 `inline + 按 Hunk 分组`；旧版 `by-hunk` 偏好会迁移为 `inline + 按 Hunk 分组`。这两项也暴露在设置页的「高级 / 视图」中。

### 语法高亮与行内变化标注
前端根据文件扩展名映射到具体的语言类型，并调用高亮引擎进行按行渲染。为保证性能，高亮开关状态也是可持久化的。语法高亮入口归入主工具栏「更多操作」菜单，并同步暴露在设置页「高级 / 视图」中；文件 diff 顶部不再单独放置语法高亮按钮。

配对的删除 / 新增行会叠加行内变化标注，用 `word-del` / `word-add` mark 显示具体变化位置。该标注覆盖左右分栏、单列、按 hunk 分组和完整文件视图；启用语法高亮时，前端先保留 highlight.js token，再在对应文本范围内插入变化标注。行内匹配优先按单词 / 标识符片段对齐，避免跨不同变量名强行匹配零散字符；单侧删除 / 新增只在无内容的一侧插入窄占位标记：旧侧为空、新侧有内容时标旧侧，新侧为空、旧侧有内容时标新侧；若两行相似度过低（例如完全不同的 hash / ID），前端只保留行级新增 / 删除背景，不做行内对比。

Vue 单文件组件使用 block-aware 高亮：前端按完整文件内容识别 `template` / `script` / `style` 区域，再对 diff 行按旧侧 / 新侧行号分派到 HTML、JavaScript / TypeScript、CSS 高亮器。普通文本 diff 仍保持逐行渲染，避免引入整文件语法解析带来的性能和加载成本。

### 忽略空白变更

文本 Diff 工具栏可切换“忽略所有空白变更”，偏好由 `ui` store 全局持久化并同步暴露在设置页。WIP 与历史提交的单文件 IPC 都把该状态传给 libgit2 `DiffOptions`；文件列表和提交级统计仍保留原始结果，因此纯空白文件不会从变更清单消失，只会在正文显示无内容变更。

切换时只强制重载当前文件：WIP 走 `diff` store，普通提交走 `history` store，文件历史弹窗重载当前历史条目。各入口用请求序号丢弃快速连续切换产生的旧响应。图片与文档预览不展示该开关；SVG 进入文本模式后可用。Hunk 操作只作用于过滤后仍可见的 Hunk。

### 变更跳转
通过收集当前视图中所有变更块的 DOM 位置，实现基于滚动位置的“上一个/下一个”精确跳转。

关闭按 Hunk 分组时，跳转目标是完整文件中的变更组；开启分组时，跳转目标仍是 hunk 块。点击普通文本 Diff 正文后，无修饰键的 `↑/↓` 会接管为上一 / 下一变更跳转，并阻止事件继续冒泡到外层历史列表；带修饰键的组合键和输入控件内按键不接管。跳转后当前变更块用最左侧竖线和顶部 / 底部细线标出当前位置，不覆盖新增 / 删除行的红绿语义，也不在代码区左侧增加额外竖线。工具栏的上一 / 下一变更按钮采用上下排列，并在旁边显示当前序号与变更总数。当前变更索引由 `DiffView` 统一维护，因此在 inline 与 side-by-side 之间切换时继续保持当前块高亮；切换布局或按 Hunk 分组时，前端会用当前顶部可见旧 / 新侧行号作为滚动锚点，切换后尽量保持相同起始行。切换到另一个文件或提交上下文时，Diff 正文从顶部开始展示，避免沿用上一个文件的滚动位置，并清空当前变更块高亮。

### 媒体预览
- **位图/SVG**：针对图片文件，不展示字符差异，而是直接拉取 Base64 字节流进行并排展示。
- **PDF/DOCX/PPTX**：PDF 使用浏览器内置 PDF 视图并排预览；DOCX / PPTX 第一版展示抽取文本预览。三者都在预览下方展示抽取文本的行级 / 词级高亮 diff，并复用全局 inline / side-by-side 布局；预览区与抽取文本 diff 之间的分割线可上下拖动，比例持久化到本地存储；按 Hunk 分组选项只决定展示完整上下文还是变更块上下文。
- **按需加载**：大文件预览受限于大小阈值，以避免内存和 IPC 通信过载。
- **WIP 兼容性**：对于工作区中尚未暂存的新文件，通过直接读取磁盘文件来获取最新内容。

## 性能取舍

- **回调节流**：在解析大型 Diff 时，后端应控制数据组装频率。
- **按需拉取**：二进制内容和完整文本内容都按需读取。完整文本复用原始内容读取阈值，超限时不强行渲染全文件。
- **过滤重载范围**：空白过滤保持单文件 pathspec，不触发工作区状态、提交列表或提交详情重算。
- **文档文本截断**：PDF / DOCX 文本抽取沿用原始字节读取阈值，并对返回文本做二次截断，避免大文档拖慢 IPC 和渲染。
- **子集高亮**：仅注册主流编程语言的高亮支持，平衡首屏加载速度与功能覆盖面。
