# 06. Diff 查看器

Diff 查看器服务于 **WIP 工作区 diff** 和 **提交内 diff**。两种场景共享同一套后端数据契约和前端渲染组件。

## 核心职责

- **数据获取**：根据当前仓库路径、文件路径、是否已暂存或特定提交 OID，计算并返回结构化的差异数据。
- **多模式展示**：支持左右分栏（Side-by-Side）和行内（Inline）两种布局，并提供独立的按 Hunk 分组选项。关闭分组时用完整文件上下文阅读，开启分组时用变更块聚焦阅读。
- **交互功能**：支持语法高亮、变更块快速跳转、图片/SVG 预览。
- **提交回滚**：提交 diff 可按 Hunk 反向应用到工作区；该入口只在开启按 Hunk 分组时展示，完整文件上下文模式不显示 Hunk 回滚操作。
- **WIP 区块索引操作**：工作区 diff 可在按 Hunk 分组时对单个 Hunk 执行暂存或取消暂存，操作目标是 Index。

## 模块划分

- **后端 (`commands/diff.rs`)**：负责调用 Git 引擎获取差异。针对工作区 diff，会包含未追踪（Untracked）文件的内容。
- **前端组件 (`components/diff/`)**：
  - `DiffView`：主入口，负责图片 / SVG / 文本 diff 分流，并接线具体渲染组件。
  - `DiffToolbar`：承载布局切换、按 Hunk 分组开关、语法高亮、搜索入口、变更块跳转和 SVG 图片 / 文本切换。
  - `InlineDiff`：渲染行内流式布局；关闭分组时显示完整文件，开启分组时按 hunk 分块。
  - `SideBySideDiff`：渲染左右对比布局；关闭分组时处理完整文件行对齐，开启分组时只渲染 hunk 内容。
  - `ImageDiff`：处理位图和 SVG 的特殊对比展示。
- **前端逻辑 (`composables/diff/`)**：
  - `useDiffSearch`：管理 diff 搜索框状态，并响应全局搜索信号。
  - `useRevertHunk`：管理提交 diff 的 hunk 反向应用操作。
  - `useWipHunkAction`：管理工作区 diff 的 hunk 暂存 / 取消暂存操作。
- **逻辑工具 (`lib/highlight.ts`, `lib/wordDiff.ts`, `lib/fullFileDiff.ts`)**：提供语法高亮映射、词级差异计算和完整文件 diff 行构造。
  - `lib/hunkPatch.ts`：根据 `FileDiff` 与 Hunk 方向构造可应用的单 Hunk patch。

## 数据契约

后端返回的差异数据结构应包含以下关键信息（详情见 `src/types/git.ts::FileDiff`）：
- **文件路径**：旧路径与新路径（处理重命名）。
- **差异统计**：新增行数与删除行数。
- **Hunk 列表**：每个 Hunk 包含补丁头（Header）及具体的行数据。
- **Blob 引用**：旧版与新版的 Blob OID，用于按需拉取原始内容（如图片预览）。

关闭按 Hunk 分组时，Inline / Side-by-Side 不要求后端返回全量上下文；前端根据 Blob 引用和工作区读取接口按需加载完整旧 / 新文本，再用 hunk 元数据补齐未变化行。读取失败或超过原始内容读取阈值时，文本视图回退到后端 hunk 数据。

## 关键特性实现策略

### 查看模式持久化
用户选择的布局模式和按 Hunk 分组开关会分别持久化到本地存储，以便在不同会话和仓库间保持一致。新用户默认使用 `inline + 按 Hunk 分组`；旧版 `by-hunk` 偏好会迁移为 `inline + 按 Hunk 分组`。这两项也暴露在设置页的「高级 / 视图」中。

### 语法高亮
前端根据文件扩展名映射到具体的语言类型，并调用高亮引擎进行按行渲染。为保证性能，高亮开关状态也是可持久化的。

Vue 单文件组件使用 block-aware 高亮：前端按完整文件内容识别 `template` / `script` / `style` 区域，再对 diff 行按旧侧 / 新侧行号分派到 HTML、JavaScript / TypeScript、CSS 高亮器。普通文本 diff 仍保持逐行渲染，避免引入整文件语法解析带来的性能和加载成本。

### 变更跳转
通过收集当前视图中所有变更块的 DOM 位置，实现基于滚动位置的“上一个/下一个”精确跳转。

关闭按 Hunk 分组时，跳转目标是完整文件中的变更组；开启分组时，跳转目标仍是 hunk 块。切换布局或按 Hunk 分组时，前端会用当前顶部可见旧 / 新侧行号作为滚动锚点，切换后尽量保持相同起始行。

### 媒体预览
- **位图/SVG**：针对图片文件，不展示字符差异，而是直接拉取 Base64 字节流进行并排展示。
- **按需加载**：大文件预览受限于大小阈值，以避免内存和 IPC 通信过载。
- **WIP 兼容性**：对于工作区中尚未暂存的新文件，通过直接读取磁盘文件来获取最新内容。

## 性能取舍

- **回调节流**：在解析大型 Diff 时，后端应控制数据组装频率。
- **按需拉取**：二进制内容和完整文本内容都按需读取。完整文本复用原始内容读取阈值，超限时不强行渲染全文件。
- **子集高亮**：仅注册主流编程语言的高亮支持，平衡首屏加载速度与功能覆盖面。
