# 07. 分支与标签管理

本模块负责本地分支、远程分支以及标签（Tags）的全生命周期管理，提供直观的层次化浏览与快速切换能力。

## 核心职责

- **多维浏览**：通过侧边栏（快速切换）与独立列表页（清单管理）展示分支信息。
- **引用操作**：处理分支的创建、检出（Checkout）、切换、删除及远程跟踪关系。
- **标签管理**：支持轻量标签与附注标签的创建、展示及远程同步状态追踪。

## 分支视图与交互

### 本地分支 (Local Branches)
- **层次化展示**：侧边栏本地分支按 `/` 自动构建树形分组；单段分支直接作为根级叶子显示，多段分支挂到对应目录下，便于管理大量 `feature/...`、`release/...` 分支。文件夹折叠与分支选择使用原生按钮，支持键盘聚焦和 Enter / Space 操作；文件夹同时暴露展开状态。
- **即时搜索**：悬停列表区域时标题栏显示放大镜，可按完整分支名进行不区分大小写的过滤；搜索期间命中分支的树路径自动展开，清空后恢复用户原有的折叠状态。
- **状态指示**：实时标识当前活跃分支（HEAD）并展示与上游分支的同步偏差（Ahead/Behind 计数）。当前激活的本地分支及其关联的上游远程分支会在视觉上同步高亮。
- **首次发布**：当前分支没有 upstream 时，工具栏将 Push 明确显示为 Publish；成功推送到所选 remote 的同名分支后自动建立 tracking，随后立即显示 upstream 与 ahead / behind。已有 upstream（包括对应远端引用已 gone）时始终保留原配置，即使用户另选 remote 推送也不改写。
- **游离状态**：当处于游离头指针（Detached HEAD）状态时，树根顶部会自动注入一个虚拟的 `HEAD` 项，以明确指示当前的检出状态。
- **快速切换**：支持通过侧边栏双击或右键菜单切换分支。工作区 clean 时直接切换，失败通过非阻塞 Toast 反馈；存在 staged / unstaged / untracked 改动时，先明确选择把改动安全携带到目标分支，或 Stash 后留在侧边栏稍后恢复。确认请求绑定仓库、HEAD、目标分支 OID 与改动路径；任一上下文变化都会拒绝旧请求。携带模式遇到 checkout 冲突会停在原分支并保留选择框，可立即改选 Stash；Stash 成功但切换失败时不自动 pop，避免二次冲突。
- **历史图 Solo 入口**：当前本地分支的右键菜单可切换 active repo 的 `Solo 当前分支` 模式；开启后当前分支行右侧显示轻量 `SOLO` 标记，语义与 `docs/04-history.md` 中的 first-parent 历史过滤一致。
- **分支清理**：提供删除非当前分支的安全入口，确认框展示本地与远端目标的短 OID，并在写入前校验引用仍指向用户确认的对象。仅当 upstream 引用仍存在且已加载时提供组合删除；upstream 已 gone 时明确只删除本地分支。组合删除先用精确 lease 删除远端，再重新校验并删除本地，因此远端被并发推进或服务端拒绝时不会提前丢失本地分支。
- **创建上下文保护**：历史页和分支页的新建分支表单保存打开时的仓库与提交 OID；打开后切换仓库会保留输入并拒绝把旧请求应用到新仓库，切回原仓库后可继续。创建后立即切换也显式作用于同一仓库。
- **Worktree 起点保护**：新建 linked Worktree 的起点下拉同时展示分支名与短 SHA；提交时携带完整 OID，后端在创建分支或目录前复核引用仍指向该提交。外部 Fetch / Reset 移动起点时要求刷新重选，不静默改用新提交。

### 远程分支 (Remote Branches)
- **层次化展示**：系统根据远程分支的命名路径自动构建树形结构，方便在大规模仓库下快速定位。
- **即时搜索**：与本地分支共用相同的完整名称过滤与搜索期间自动展开语义。
- **智能检出**：检出远程分支时，系统会自动建议本地分支名并建立相应的上游跟踪关系。
- **检出表单保护**：检出表单冻结打开时的仓库、远程分支候选和本地名称集合；切换仓库不会让旧候选落到新的 active repo。
- **删除保护**：远程分支确认展示目标短 OID；执行时通过显式 force-with-lease 把目标校验与删除放在同一次 push 中，确认后目标变化则拒绝删除。

### 分支管理页
提供全量的分支列表，支持根据名称快速筛选，并提供集中式的分支维护入口。新建入口打开后焦点直接进入分支名输入框，可用 Enter 提交、Escape 收起；非当前本地分支使用原生按钮，可通过键盘聚焦并切换。

## 标签管理 (Tags)

- **类型支持**：区分轻量标签（仅引用）与附注标签（包含作者信息与描述消息）。
- **视觉增强**：在侧边栏按时间或名称排序展示，并根据远程同步状态叠加视觉反馈（详情见 `docs/04-history.md`）。
- **即时搜索**：侧边栏标题栏提供放大镜入口，可按完整 Tag 名称即时过滤已加载列表。
- **操作集成**：支持直接从特定历史提交点创建标签，实现版本的快速标记。
- **创建上下文保护**：创建 Tag 的表单保存打开时的仓库、提交和 Tag 类型；上下文变化时保留输入并拒绝执行旧请求。
- **强推保护**：选择 remote 后先读取同名远端 Tag；远端不存在或精确对象一致时按普通 Push 处理，不展示无意义的危险确认。确需覆盖时显示 remote 与本地 / 远端对象短 OID，后端在执行前复核两侧目标；确认期间任一目标变化会拒绝旧请求。
- **删除保护**：本地与远端删除都显示并校验 Tag 的精确对象；单独删除远端时在确认前选择 remote。组合删除先选择并验证远端，按“远端后本地”执行，remote 选择取消、远端失败或仓库上下文变化时不会提前删除本地 Tag。

## 数据集成逻辑

### 状态采集
后端周期性地或基于变动事件扫描所有引用（Refs），计算分支间的拓扑偏差，并将其转换为前端可直接渲染的 `BranchInfo` 与 `TagInfo` 结构。`TagInfo` 同时保留标签引用直接指向的对象与 peel 后的 commit：前者用于判断附注 Tag 是否被重建和保护强推目标，后者用于历史跳转。

首次 Publish 成功后，Push 引擎按本次实际 remote 建立同名 upstream；只有远端写入成功且本地分支原先没有 upstream 才修改 tracking 配置。该行为等价于标准 Git 的首次 `push --set-upstream` 语义，不受 GitUI 默认 remote UI 偏好影响。

### 检出逻辑
分支检出不仅涉及引用的切换，还会同步协调工作区的文件更新。脏工作区统一提供三种改动去向：携带模式采用 safe checkout，防止因冲突导致代码丢失；Stash 模式复用包含 untracked 的现有 stash 流程，并在消息中记录来源 / 目标分支；丢弃模式先复用工作区的可恢复丢弃流程，把普通文件当前版本移入系统废纸篓，再执行 safe checkout。丢弃或 Stash 已完成但检出失败时，对话框保留中间状态，重试不会重复处理改动。切换成功后立即刷新工作区，不依赖 watcher 的防抖延迟；UI 不提供绕过这些保护的 force checkout 入口。

### 树形构造
前端通过对分支全路径的路径分析，动态生成嵌套的树形数据结构，以降低多远程、多层级场景下的认知负担。本地分支使用本地树构造逻辑，避免单段分支被包成多余目录；远程分支仍以 remote 名称作为根节点，并可预先显示尚未 fetch 出分支的 remote。

## 刷新策略

分支与标签的状态会随仓库变动事件（如 Fetch、Push、Commit 或手动切换）自动保持同步。针对可能改变 HEAD 或同步计数的关键操作，系统会执行原子化的全量刷新。
