# 08. 远程操作

本模块负责与远程仓库的交互，涵盖 Fetch、Push、Pull 等核心同步命令，以及远程 URL 与凭据的管理。

## 核心职责

- **数据同步**：执行远程数据的拉取（Pull/Fetch）与推送（Push）。
- **凭据管理**：协调不同协议下的身份验证，包括 SSH 密钥对、HTTPS 凭据助手等。
- **冲突预防**：在执行非快进（Non-FF）推送或存在本地冲突时提供安全防护。
- **交互引导**：在大仓库、多远程节点场景下提供直观的节点选择与进度反馈。

## 网络协议与底层驱动

系统采用混合驱动策略以确保跨平台的高兼容性：

1. **HTTPS 协议**：主要通过内置的 Git 引擎库实现，集成系统级凭据管理器（如 Keychain、Credential Manager）。
2. **SSH 协议**：为了复用用户已有的 SSH 配置与代理环境，系统对于 SSH 类型的远端操作采用桥接宿主环境原生工具的策略。这确保了在不同操作系统下都能获得稳定、一致的验证体验。

Windows 下，后台子进程统一使用无控制台启动配置。SSH shellout 由 `git/shellout.rs` 构造，并在未检测到用户显式 SSH 命令配置时注入 GitUI 内置 SSH proxy；proxy 模式只转发到真实 `ssh.exe`，不启动 Tauri UI。HTTPS 凭据助手使用带 Windows 隐藏进程修复的 `git2-rs`，避免远程 Tag 查询及其他认证操作出现短暂控制台窗口。

Unix / macOS 下，系统 Git shellout 会补齐宿主工具 PATH：合并用户 login shell 中的 PATH 与常见包管理器、本地 bin 目录，再传给 `git` 及其 hook 子进程。这样从 Finder / Dock 启动的 GUI 应用也能让 pre-push hook 找到 `git-lfs` 等命令行工具；找不到系统 `git` 本体时仍按命令失败处理。

## 同步流程设计

### Fetch 与状态更新
Fetch 操作不仅同步远程对象，还会原子化地触发本地分支、提交历史以及远程标签状态的刷新。系统会自动检测远程标签的同步情况并更新 UI 指示（详见 `docs/04-history.md`）。

Fetch All / Fetch Tags All 会逐个尝试所有 remote，并在结束后聚合失败项；只要存在失败 remote，命令会返回包含 remote 名称的错误，避免部分失败被误判为成功。

### Pull 与合并策略
Pull 操作集成了 Fetch 与随后的合并。
- **模式支持**：默认支持快进合并（Fast-forward），并在允许的配置下支持产生合并提交。
- **脏工作区引导**：工具栏检测到 staged、unstaged 或 untracked 改动时，先显示改动数量；用户确认后自动 stash（含 untracked）、执行 Pull，并在仓库回到 clean 状态后恢复原始改动。clean 工作区仍直接 Pull。
- **恢复安全性**：Pull 留下 merge / rebase 等中间态、无法确认仓库状态或 stash pop 冲突时不强行恢复；临时 stash 保留在现有 Stash 列表，并提示用户先处理当前状态后手动恢复。
- **后端安全线**：`pull_branch` 只接受 clean 且没有未完成 Git 操作的仓库，并在 fetch 前统一检查，防止过期 UI 状态或其他调用绕过保护后进入强制 checkout。
- **分叉处理**：当检测到远程分支与本地存在偏离（Diverged）且所选模式无法处理时，系统会中止操作并提示用户改用 merge 或 rebase。

### Push 操作
- **分支推送**：执行当前分支到所选 remote 的同名分支同步。系统遵循保守策略，不默认执行强制推送。
- **首次发布**：当前分支没有 upstream 时，工具栏显示 Publish；任一 Push 模式成功后建立所选 remote 的同名 tracking。远端失败不写配置，已有 upstream 不因另选 remote 被覆盖。
- **标签推送**：支持对特定标签进行远程同步，并提供防重写保护。

## 交互设计

- **多远程选择**：在配置了多个远程节点（Remotes）时，系统会提供交互式的选择菜单。
- **默认远端偏好**：Push / Pull 的远端选择菜单允许在 remote 名字后设置或取消默认远端。默认远端按仓库路径保存在 UI 偏好中，不写入 Git 配置；默认 remote 仍存在时，Push / Pull 会直接使用它，若 remote 被删除或重命名则自动回退到选择菜单。
- **进度反馈**：网络同步过程中的进度（如接收对象、解析增量、检出文件）会实时回传并展示在 UI 界面上。
- **并发控制**：为每个仓库维护独立的同步忙碌状态，防止并发冲突。
- **上下文校验**：远端选择或脏工作区确认期间若用户切换了仓库 / 分支，丢弃旧 Pull 请求，避免在错误上下文执行。
- **Push 上下文校验**：Push 的远端菜单等待期间同样校验仓库 / 分支，防止把旧请求应用到后来切换的上下文。

## 凭据回馈机制

对于 HTTPS 协议，系统会尝试按顺序匹配多种凭据源（如系统代理、配置文件、SSH Agent 等），以最大限度地实现无感知认证。当所有尝试均失败时，会向用户反馈明确的认证失败信息。
