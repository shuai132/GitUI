# 09. 子模块管理 (Submodule)

GitUI 对子模块的管理目标是实现父仓库与子仓库的无缝联动，使其在操作体验上接近于两个独立的对等仓库。

## 核心职责

- **状态监测**：实时识别子模块的初始化状态、克隆进度及本地修改情况。
- **生命周期维护**：提供子模块的初始化（Init）、更新（Update）、URL 变更及彻底移除（Deinit）功能。
- **关联导航**：支持将已克隆的子模块作为独立的仓库实例在系统中激活并管理。

## 状态分类与逻辑

系统对子模块的状态进行多维度评估，包括：
- **一致性**：当前子模块提交是否与父仓库记录相匹配。
- **活跃度**：子模块是否已在本地配置文件中注册并完成克隆。
- **存在性**：子模块路径在磁盘上的真实存在情况。
- **脏改动感知**：监控子模块内部是否有未暂存或未提交的本地修改，并在 UI 上通过视觉提示进行反馈。

## 关键管理动作

### 初始化与同步 (Init / Update)
- **Init**：在本地配置中注册子模块信息。
- **Update**：负责将子模块同步至父仓库指定的版本。在缺失时，系统会自动执行克隆逻辑并协调身份验证。

### 深度移除 (Deinit)
与标准的 Git 命令相比，GitUI 的“删除子模块”动作为用户执行了更彻底的清理：
- **文件清理**：工作区目录及内部存储的 Git 模块元数据移入系统废纸篓，不直接永久删除；任一步回收失败时停止后续配置与 Index 修改。
- **配置剥离**：从项目及全局配置中彻底移除相关条目。
- **索引更新**：自动更新父仓库的索引，用户只需执行一次提交即可完成清理闭环。

## 交互设计

- **侧边栏集成**：子模块以列表形式展示在侧边栏，通过图标状态反映其健康程度。
- **即时搜索**：悬停列表区域时标题栏显示放大镜，可按 Submodule 名称、相对路径或 URL 过滤已加载列表，便于在包含大量子模块的仓库中定位。
- **独立管理**：点击已克隆的子模块可将其直接“激活”为系统的主操作仓库，实现父子仓库间的秒级切换。
- **便捷编辑**：支持直接通过对话框修改子模块的远程 URL 并自动执行同步（Sync）。
- **表单上下文保护**：Add / Edit 表单绑定打开时的仓库，切仓后保留输入但拒绝应用到新仓库；Edit 还冻结原目标与 URL，后端写 `.gitmodules` 前再次校验预期旧 URL。
- **精确删除确认**：确认框绑定仓库与 Submodule 状态快照；带未提交修改时单独警告并说明废纸篓恢复方式，确认期间仓库或目标变化会取消旧请求。
- **动作上下文保护**：侧边栏菜单的 Init、Update、Edit、打开与删除均绑定菜单打开时的仓库和 Submodule 状态；切仓或状态变化会取消旧动作。各入口调用 Submodule store 时显式传递 repoId，异步打开子仓库前也会复核父仓库上下文。
- **仓库树归属**：当 direct submodule 已被加入“所有仓库”名册时，它会在父仓库下方以子层级展示，帮助用户识别父子关系；该层级不改变子模块作为独立仓库被激活和操作的能力。
- **工作区入口**：父仓库工作区中的 submodule gitlink 变更会以专用项显示，右键可直接打开已克隆的 submodule 仓库；未 init、未 clone 或工作区不存在时提供 init / update 动作。
- **历史入口**：提交详情中的 submodule gitlink 变更同样支持右键打开当前工作区中的对应 submodule 仓库；若当前 direct submodule 尚不可打开，可直接从菜单执行 init / update。历史中的旧 submodule 即使已从当前 `.gitmodules` 移除，也会通过 gitlink 文件 mode 显示为 submodule 项，但不会提供当前工作区动作。

## 技术决策

1. **Direct 关系管理**：系统目前专注于当前活跃仓库和已打开仓库之间的 direct submodule 关系。深层子模块只有在其直接父仓库也被打开并能提供 `list_submodules` 数据时，才会作为对应父节点的子层级展示。
2. **安全优先**：在执行删除等破坏性操作前，系统会提供详尽的影响范围说明；本机 Submodule 数据只移入系统废纸篓，父仓库产生的删除仍通过 Git 变更供用户复核与提交。
3. **性能平衡**：子模块状态的刷新策略与主仓库工作区保持一致，通过订阅变动事件实现按需加载，避免在大规模项目下的无效资源消耗。
