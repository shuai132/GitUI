# 12. 设置 (Settings)

本模块管理应用的外观偏好、功能开关及个性化定制，确保用户能根据自身习惯调整工作环境。

## 核心职责

- **偏好管理**：涵盖语言、主题、字体、强调色及布局间距等个性化设置。
- **状态同步**：确保所有设置项变更后能实时生效，并在不同会话间正确持久化。
- **视觉反馈**：提供平滑的主题切换体验与精细的样式微调能力。

## 设置维度

### 视觉偏好
- **语言支持**：支持多语言切换，详情见 `docs/13-i18n.md`。
- **主题模式**：支持深色、浅色及跟随系统的自动切换模式。
- **色彩定制**：允许用户自定义系统强调色（Accent Color），以匹配个人审美。

### 界面元素调整
- **行间距与分隔线**：支持调整提交历史行的间距、分隔线样式及透明度，优化视觉密度。
- **提交图风格**：支持多种提交图连接线风格（如圆润、直角、斜线），详情见 `docs/05-commit-graph.md`。
- **历史列表列偏好**：提交历史的「变更」列默认隐藏，用户可在设置页「高级 / 视图」或工具栏「更多操作」菜单中手动开启；历史列表列顺序通过列头拖拽调整并持久化。
- **高级视图偏好**：Diff 默认布局、Diff 按 Hunk 分组、Diff 语法高亮、默认忽略空白变更、远程分支显示、调试日志和提交详情文件列表位置等全局视图开关可在「高级 / 视图」中调整，并可单独恢复该组默认值。空白过滤也可从 Diff 工具栏即时切换，变更后只重载当前文件。`Solo 当前分支` 是仓库级历史浏览状态，只在工具栏 Actions 和当前本地分支右键菜单中切换。
- **Git 行为偏好**：自动 fetch 间隔可在「高级」中配置，前端偏好持久化后通过 `set_auto_fetch_interval` 同步给后端服务。同步期间禁用重复选择；后端更新失败时恢复原显示与持久化值，并使用非阻塞提示说明设置未生效。
- **更新检查**：「更新」页支持启动时自动检查或手动检查，策略选项使用可聚焦的原生按钮并暴露当前选中状态，支持键盘操作。自动和手动检查都会在拿到明确结果后刷新“上次检查”时间；网络失败不刷新，避免把未完成检查误记为成功。发现新版本时优先展示 GitHub Release 正文；Markdown 转换后的 HTML 经 DOMPurify 消毒，且正文请求绑定当前可见版本，旧响应不能覆盖新版本。版本变化会重置旧的下载完成 / 错误展示；若应用内无法加载正文，则提供 GitHub Releases 入口作为 fallback，外链或重启失败使用非阻塞提示。
- **快捷键偏好**：设置页提供独立快捷键面板，所有动作绑定由 `shortcuts` store 持久化；“快速切换仓库”默认使用 `Cmd/Ctrl + Shift + O`，触发后复用“所有仓库”搜索完成键盘选择。WIP 视图提供当前文件与全部文件的暂存 / 取消暂存键位，以及提交信息聚焦键位；默认值与 GitKraken 保持一致，均可改绑或清除。全局派发只在非输入焦点下生效，提交消息输入框内的提交快捷键由提交表单本地处理。`Esc` 优先交给快捷键录制或最上层模态弹窗处理，取消当前局部交互后不继续透传到全局快捷键或窗口级逻辑。
- **插件管理**：设置页提供独立插件面板，通过 `plugins` store 管理本地可信插件的安装、刷新、启用、禁用和卸载；插件能力与贡献点见 `docs/17-plugins.md`。

### 字体与排版
- **UI 字体**：自定义界面整体字体及字号。
- **代码字体**：针对 Diff 查看器及提交哈希等位置，支持独立的等宽字体与字号配置。

## 实现机制

### 实时生效与持久化
系统采用“所见即所得”的策略，用户在设置面板中的每一项修改都会：
1. **实时触发**：通过响应式状态管理立即应用到 DOM 结构。
2. **异步落盘**：自动保存到本地存储，确保配置的安全性与响应速度。

### 样式穿透
配置通过底层样式的变量化实现。系统在根元素级别控制核心变量（如字体、色值、行高），各子组件通过继承或引用这些变量来实现全局风格的统一。

### 重置策略
提供按分类恢复默认设置的功能，方便用户快速回归初始状态。

## 关键技术决策

1. **同步加载保障**：核心偏好设置在应用启动的极早期完成加载与应用，以避免界面闪烁（FOUC）。
2. **布局稳定性**：对于可能大幅影响布局的设置（如行高、字号），系统通过容器尺寸探测与虚拟滚动重排机制确保界面的稳定性。
3. **隔离性原则**：UI 偏好数据与仓库业务数据严格隔离存储，确保偏好的全局性与独立性。
